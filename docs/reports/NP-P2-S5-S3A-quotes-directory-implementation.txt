5. SEARCH AND PAGINATION DESIGN
======================================================================
- Input validation (database): status in a closed set; sort in a closed set; limit 1–100; offset 0–100000; search
  ≤ 200 characters. Anything else → ZW006. Never a silent default.
- The app's parseDirectoryParams maps unknown URL values to the defaults before calling, so a hand-edited URL never
  errors (E2E F8). The page number is capped at the maximum offset.
- Search:
  - case-insensitive substring on opportunity title and contact display name;
  - an exact quote number for "12", "#12", "Quote 12", "Estimate 12";
  - an exact kind for "estimate(s)" / "quote(s)".
  - The user's text becomes a LIKE pattern with \ % _ escaped. It is a bound value, never concatenated into SQL (SQL Q4 /
    Q5; E2E F2 / F3).
  - Free text (terms, labels, notes, withdrawal reasons) is never searched (Q6). No medical or route data exists in
    quotes.
  - A bare number also matches titles or names containing those digits (documented, by design).
- Pagination:
  - server-side LIMIT / OFFSET, 25 per page in the UI;
  - total_count is the filtered total (a window count) and is returned on every row;
  - a page past the end returns no rows, and the page says so with a link to page 1 (it doesn't show an empty
    directory);
  - pages cover every quote exactly once (SQL P1; E2E P3 / P4).
- Sort:
  - newest (default) / oldest (created_at), valid_until (soonest first), number (highest first);
  - every order ends with quote_number desc, id, a unique tie-breaker, so pages are stable (P1, P5).
- The rules live in the database and the pure core (quotes-core.ts). The visual components only render already-formatted
  rows.

9. D1 UX FIX
======================================================================
- Defect: the S2 production smoke found that after "Withdraw draft" the confirmation could vanish. The dialog was rendered
  as `open === "withdraw" && draft && …`. The action's revalidation re-rendered the page with draft = null and unmounted
  the dialog before its success effect posted the message.
- Fix (QuoteDraftControls.tsx, narrow):
  - when the edit or withdraw dialog opens, the draft is captured in state (`target`);
  - the dialog renders from that snapshot (`open === "withdraw" && target && …`), so it stays mounted through the
    revalidation, hands over its confirmation once (ref-guarded), then closes.
  - The confirmation line is an accessible role="status" region in the controls, which remain mounted (the panel offers
    the create control again).
  - The editor and withdraw dialogs themselves are unchanged.
- VERIFIED (E2E D1): three consecutive withdrawals on three opportunities. After each, and 2.5 s after the revalidation:
  - "Draft withdrawn. It stays in the quote history." is visible, with role=status;
  - the quote is withdrawn in the database and shown in History;
  - no draft remains;
  - exactly one quote row and one plus_quote_withdrawn audit row (no duplicate withdrawal, no delete).
  Result: 3 of 3.
- The unit test asserts the snapshot pattern and that no `open === "withdraw" && draft` remains.

14. PERFORMANCE CONSIDERATIONS
======================================================================
- One page per request (≤ 100 rows; 25 in the UI) and one summary aggregate. Nothing is mass-fetched to the browser.
- Index:
  - plus_quotes_org_status_valid_idx (organization_id, status, valid_until) serves the status filters, the derived
    Expired filter (status = 'sent' AND valid_until < today) and the four filtered counts;
  - the organization filter alone is served by the existing org-leading indexes (organization_id, opportunity_id,
    created_at desc) and unique (organization_id, quote_number).
- Sort: the ORDER BY uses a sort-mode CASE, so the database sorts the filtered rows of ONE organization. The cost grows
  with that organization's own quote count (n log n). A sort-specific index was deliberately not added, because no
  single index serves all four modes.
- Search: substring ILIKE on title / contact name scans the organization's joined rows. No trigram index is added (not
  justified at this volume).
- total_count is a window count over the filtered set.
- OFFSET pagination: deep pages scan and skip earlier rows. The offset is capped at 100000.
- Expected behaviour as volume grows:
  - up to tens of thousands of quotes per organization: comfortably interactive;
  - at hundreds of thousands per organization, consider keyset pagination (the stable tie-breaker already exists) and
    a pg_trgm index for search. Both would be additive, with no change to the RPC result shape for the UI.
- No query plans were captured at volume. These figures are design estimates, not benchmarks (NOT RUN).
