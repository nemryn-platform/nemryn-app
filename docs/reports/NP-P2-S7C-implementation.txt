3. IMPLEMENTATION
======================================================================================================================
3.1 Navigation (Phase 1)
- Growth children: Dashboard, Inquiries, Pipeline, Contacts, Estimates & Quotes, Tasks. Active state for the
  sub-tree; context header shows "Growth > Inquiries".
- Badge: the layout calls plus_count_new_inquiries only when Growth is visible (request-cached). A visible number
  (99+ cap) plus screen-reader text "N new"; in the icon rail a dot plus aria-label "Growth, N new inquiries".
  Any read failure shows no badge (never an error page). Conversions / dismissals revalidate the /operations layout,
  so the count updates immediately.

3.2 Inquiries list
- plus_list_inquiries: status filter New (default) / Converted / Dismissed / All, search (name, phone, email,
  max 200 chars), 25 per page with Previous / Next, total count. Malformed URL parameters fall back to defaults.
- Columns: From (name + phone / email; the row link), About, Service, Received (workspace timezone), Status
  (badge; dismissed rows show the reason). Whole row opens the inquiry (DataTable navigableRows, keyboard link).
- Loading via server render; error state with Retry; empty states for "no new inquiries" (points to Settings) and
  for filters; past-the-end page message. Container-query filter layout (same pattern as Quotes).

3.3 Inquiry detail
- plus_get_inquiry; unknown, foreign and malformed ids render the same not-found (no existence oracle).
- Panels: Status (new / converted with contact + opportunity links and who / when / dismissed with reason, note,
  who / when); What they sent (all submitted fields; question kept verbatim); "Communication boxes on the form"
  ("Ticked: …" / "Not ticked: … (no permission given)" plus a note that a tick becomes consent only on conversion and
  an unticked box is never permission); Possible matches (plus_list_inquiry_duplicate_hints: contacts and other new
  inquiries, "hints only, nothing is merged"); How they found you (UTM / page / referrer, shown only when present).
- Actions in the page header: Convert + Dismiss (status new), Reopen (status dismissed). Read-only viewers (READ
  grant, read_only workspace) see "View only" and no controls; the RPCs refuse them anyway (ZW001).

3.4 Conversion (Phase 2) — plus_convert_inquiry
- Dialog: "Create a new contact" or "Link to an existing contact". Link targets are the matching ACTIVE contacts
  from the duplicate hints (enriched server-side with Do not contact and blank fields); link is preselected when a
  match exists and disabled when none does.
- Fill blanks: offered only when the chosen contact lacks a phone / email the inquiry has; fills empty fields only.
- Duplicate rule: "create" with a possible duplicate returns possible_duplicates; nothing is written; the dialog
  explains and the button becomes "Create a new contact anyway" (confirm flag) — or staff switch to Link.
- Do not contact: choosing a DNC contact shows a critical warning and a required "I've read this warning" checkbox;
  Convert stays disabled until ticked; the server refuses without it (ZW004 do_not_contact_acknowledgement_required).
  No consent is recorded for a DNC contact and DNC stays on.
- Consent: the browser sends NO consent values. The dialog explains in advance which ticked purposes will be recorded
  (email + phone given, matching the contact, never SMS) or that none will. The success panel reports the count
  recorded and explains every skipped pair in plain words (consent_skipped). An unticked box is never permission.
- Opportunity title optional; the placeholder is exactly the RPC's default title. Owner left unassigned (null).
- Concurrency / staleness: expected_version is the inquiry version shown; a stale dialog gets "Someone else changed
  this just now. Reload…"; nothing is written. Converted is final.
- Never creates a Core Request (verified: Requests / Passengers / Trips / notifications unchanged in every run).
- Success: explicit message, consent notes, links to the opportunity and the contact; Done refreshes the page.

3.5 Dismiss / reopen
- Reasons: Spam, Duplicate, Not relevant, Outside our service area, Other (note required for Other; max 500,
  "don't include medical details"). Reopen returns a dismissed inquiry to New. Both version-checked.

3.6 Settings -> Nemryn Plus -> Inquiry form (Phase 3)
- Shown to Organization Admins while Plus is write or read_only (same visibility as Team access); editable only in
  write. Fields: headline (1-120, required), introduction (<= 500), services = checkboxes over the workspace's
  current offerings (service_options; never airport). Server validation re-reads the allowed services server-side.
- Buttons: Create draft / Save draft; Publish (draft or disabled); Turn off (published). Saving a PUBLISHED form asks
  for confirmation first ("changes show on your website as soon as you save"), per the S7-A contract.
- Activation: when either gate is off the section says "Public inquiries aren't turned on yet" and lists both
  states — "This workspace: not turned on yet / turned on by Nemryn" (DB allowlist, read-only) and "Nemryn servers:
  not accepting / accepting public inquiries" (PLUS_INQUIRY_SUBMISSIONS, read-only). Publishing without the
  allowlist is refused by the database (ZW004 public_access_not_enabled) and explained in plain words. Neither gate
  can be changed from the app.
- Share: for published / disabled forms, the hosted link (origin/inquiry/<key>) and the copyable embed snippet
  (div data-nemryn-inquiry-form + /embed/inquiry-form.js), each with a Copy button.
- Robustness: getAppOrigin() throws by design on a misconfigured origin. That is caught: the page keeps working and
  the share area says the link can't be shown right now (seen on the local production build, whose origin is
  loopback).

3.7 Wording (Phase 4)
- Communication preferences: captured_via web_form now reads "Website inquiry form"; follow-up purpose text says
  "inquiry" (no "enquiry" remains in src/ or public/). Core "Website form" activity strings (Core request form) left
  unchanged on purpose.
- Concept B components only (PageHeader, Panel, SectionHeader, DefinitionList, DataTable, StatusBadge, Dialog,
  AttentionState, EmptyState, Brand Lock v2 tokens). No approved page was redesigned.

6. LIMITATIONS / NOTES FOR REVIEW
======================================================================================================================
- No owner selection in the convert dialog: the opportunity is created unowned (existing rules); it can be assigned
  in the Pipeline. Kept out to stay within the approved design.
- Link targets are limited to the duplicate-hint contacts (max 5, matching name / phone / email). Linking to an
  unrelated contact would need a contact picker; not in the approved design.
- Hosted link / embed snippet: the local `next start` production build refuses a loopback origin by design, so the
  E2E above exercises the fallback. Verified separately at PR preparation on `next dev` with the configured origin
  (isolated stack, local switch only): Settings link + snippet correct, hosted link opens the form, snippet on a
  separate-origin page injects the embed iframe (see docs/reports/NP-P2-S7C-pr-handoff.txt).
- Pre-existing (not changed): the Core "Use a Nemryn form" settings page calls getAppOrigin() without a fallback and
  would fail the same way on a loopback production build.
- The new-inquiry count is one extra RPC per /operations layout render, only for people who can see Growth.
- Public activation remains OFF in production (no env var, empty allowlist). Turning it on is a separate, owner-
  approved release step.
