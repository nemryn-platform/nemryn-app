======================================================================
OVERLAP-CORE DESIGN
======================================================================
src/lib/operations/trip-overlap-core.ts is pure, with no runtime imports. It is the ONE model for every surface.
  - deriveTripExtent: known [start, start + minutes) or unknown (no_schedule | no_duration).
  - intervalsOverlap: half-open; touching is not an overlap.
  - deriveResourceOverlap(target, candidates, nowMs) → { targetExtent, driver, vehicle }. Each ResourceCheck has:
      status: "overlap" | "clear" | "not_checkable" | "not_fully_checkable"
      overlaps: tripId[]
      missingExtent: tripId[]
      stillOpenPastPlannedEnd: tripId[]
  - Candidates are filtered to the same active resource, the target excluded, and non-terminal only. Ended
    assignments never count; only the active assignment's resources are used.
  - Also: overlapNotices (the one copy source), formatTripExtent ("… (next day)", "(+N days)"),
    formatDurationMinutes, assignLanes (deterministic) and deriveAxisHours.

======================================================================
MISSING-EXTENT BEHAVIOUR
======================================================================
  - The target has no duration: never an overlap. Candidates that could matter make it "not_checkable". A candidate
    that provably ends before the target starts is clear.
  - A candidate has no duration: "not_checkable" unless it starts at or after the target ends, when it provably
    cannot intersect.
  - A missing schedule is never placeable.

======================================================================
STILL-OPEN-PAST-PLANNED-END BEHAVIOUR (Q7)
======================================================================
A candidate that is non-terminal, holds an active assignment, and has a known planned end < now:
  - an intersection with its PLANNED interval is still a known overlap;
  - a target that lies (partly) after the expired planned end gives "still_open", and the resource is
    "not_fully_checkable";
  - the trip is never extended to "now" or any invented end, never called clear, and never called late (no
    threshold).
`now` is a function input. Dispatch also shows the factual "Past planned end" flag on such a block.

======================================================================
CANDIDATE-QUERY STRATEGY (including older unresolved trips)
======================================================================
getOverlapCandidates(org, fromMs, toMs) in src/lib/operations/trip-overlap.ts runs TWO bounded queries in
parallel, both on the session client (RLS) with an explicit organization_id filter:
  A. Non-terminal trips with start in [from − 48 h, to), on the existing (organization_id, scheduled_pickup_at)
     index, with the active assignment left-joined (ended_at IS NULL). Limit 2000.
  B. Non-terminal trips with start < from − 48 h that still hold an active assignment (inner join). Limit 500.
     These are the older still-open commitments needed for Q7.
Terminal trips are never fetched. Overlaps are derived in memory, with no per-trip query:
  - Dispatch: one candidate set for the day.
  - Tomorrow: one set.
  - The dialog / New Trip / Trip Detail: one set for the target window (known interval, or start + 48 h when the
    duration is unknown).
No new index was added. Everything is org + date bounded, and a vehicle partial index is only a profiling-driven
future option.
