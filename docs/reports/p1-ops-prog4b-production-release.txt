Operational notes from this release (none is a product change):
  1. The read-only Management API api-keys call (?reveal=false), used to obtain the PUBLIC publishable key for the
     R2 real-session client, still returned the LEGACY service_role key in plaintext. Only the new-style secret key
     was redacted. That key was held briefly in process memory and was never printed, stored or used. The public key's
     scratch copy was deleted after the smoke.
  2. A one-off read-only session check used supabase-js signOut() with its default "global" scope. This revoked any
     other active sessions of the synthetic Siloan admin QA account. The smoke harness itself uses scope "local".
  3. `supabase db push` printed a CLI-side pg-delta certificate error after the migration. The migration applied and
     was verified. Consider updating the Supabase CLI (installed 2.109.0; 2.118.0 is available).
