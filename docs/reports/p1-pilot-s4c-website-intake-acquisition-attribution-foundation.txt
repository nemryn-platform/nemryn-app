ATTRIBUTION PRODUCT DECISION
======================================================================
Capture the evidence first: an immutable factual snapshot of what arrived with the ORIGINAL website submission, one per
Request, to support later derivation of Requests/Trips/recurring demand/completed transportation by source, medium,
campaign, landing page and referrer host. No analytics, no scoring, no stored classification (paid/organic/social/
direct are derived later from facts), no backfill, no editing.

PUBLIC CONTRACT
======================================================================
ONE optional object `acquisition`; the object and every property optional. Old integrations unchanged.
  utmSource (<=120), utmMedium (<=120), utmCampaign (<=160), utmContent (<=160), utmTerm (<=160),
  landingPath (<=300), submissionPath (<=300), referrerHost (<=253), formVersion (<=64)

======================================================================
VALIDATION
======================================================================
Two independent, rule-identical layers: TypeScript fast pass (sanitizeAcquisition, website-intake-core.ts) and the
authoritative SQL sanitiser (public._sanitize_acquisition, internal). Rules: UTM fields trimmed, non-empty, bounded
(code points), no control characters, case preserved; paths = pathname only (leading "/", allowed RFC 3986 path
characters, no "//", scheme, host, "?", "#", whitespace, backslash); referrerHost = bare hostname, lowercased (hostnames
are case-insensitive; the only value normalised), no protocol/port/path/query, no "..", no "-." / ".-"; formVersion =
[A-Za-z0-9][A-Za-z0-9._-]*. Non-strings, unknown keys, arrays, scalars: dropped. Defence in depth: the table itself
enforces lengths, path/host/version shapes and "not empty" with CHECK constraints, so even the owner cannot store a
full URL as a path.
PRIVACY: never accepted or stored -- IP, raw user agent, fingerprints, screen data, cookies, session ids, full referrer
or landing URLs, query strings, gclid/fbclid/msclkid, tracking pixels, email tracking ids, arbitrary metadata.

======================================================================
BEST-EFFORT INTAKE RULE   (critical invariant)
======================================================================
A VALID TRANSPORTATION REQUEST NEVER FAILS BECAUSE OF ATTRIBUTION. Enforced three ways: (1) the TS validator never
returns invalid because of acquisition (garbage becomes null); (2) the SQL sanitiser never raises; (3) storage runs in
a sub-transaction: even a deliberate internal failure (test BE forces a constraint violation) only raises a content-free
warning -- the Request is still created, committed and notified with no snapshot. If no valid value survives, no row is
created. Unknown TOP-LEVEL payload keys are still rejected exactly as before (only `acquisition` joined the closed set).

IDEMPOTENCY / SNAPSHOT SEMANTICS
======================================================================
Existing idempotency (intake_integration_id, external_submission_ref ON CONFLICT DO NOTHING) remains authoritative.
Attribution is written only when the Request row was newly inserted, so a replay never adds, changes or duplicates it

grant, organization_id change blocked); no edit UI; no correction tooling (a future audited feature).
NO BACKFILL: historical Requests have none; absence displays nothing (never Direct/Organic/Unknown).
