1. CONCURRENCY HARNESS ISOLATION (FINDING, FIXED)
------------------------------------------------
Finding:
- The script copied the repository's existing concurrency-script convention: CONTAINER defaulted to
  supabase_db_ZenWard, and NEMRYN_TEST_DB_CONTAINER accepted any value.
- Run without the variable, it would therefore have written and then cleaned up throwaway rows in the owner's shared
  ZenWard dev database. It did not fail closed.
- The fictional-seed fingerprint alone cannot distinguish the two local stacks: both return 2/1/0, because both use
  the same seed. So the container identity itself must be verified.

Guard added (before ANY write; exit code 2; no override variable):
- (a) The container must equal supabase_db_NemrynS1Iso.
- (b) The database must equal "postgres".
- (c) DOCKER_HOST must be unset, and the active Docker context endpoint must be a local unix:// socket.
- (d) docker inspect must show the label com.supabase.cli.project = NemrynS1Iso, and State.Running = true.
- (e) The fictional seed fingerprint must be 2/1/0, the same fingerprint as tests/e2e/plus-quotes/_config.mjs.
- (f) The throwaway organization and both throwaway users must be freshly created, valid UUIDs, or the script refuses.
  cleanup() returns without doing anything unless all three ids are valid UUIDs. This prevents an empty or garbled id
  from ever reaching a DELETE.
The header comment documents the guard.

Verification (the guard must refuse and write nothing):

|---|---|
| NEMRYN_TEST_DB_CONTAINER=supabase_db_ZenWard | REFUSED, rc 2 |
| NEMRYN_TEST_DB_CONTAINER=some_remote_db | REFUSED, rc 2 |

Positive rerun on the isolated stack (default target, no variables): rc 0, 14 / 14 PASS, "ALL PASS".

  - 0 s6-conc-* users.

2. PRODUCTION CANNOT BE TARGETED
--------------------------------
- The script reaches Postgres only through `docker exec -i <local container> psql -U postgres`. It reads no
  connection string, URL, host, port, environment file or key, so a hosted Supabase database is not addressable.
- The guard additionally pins the container name and Supabase CLI project label, refuses any remote Docker endpoint
  (DOCKER_HOST or a non-unix context), and verifies the fictional seed.
- The new SQL suite (plus_communication_consents_tests.sql) is a single transaction ending in ROLLBACK, the
  repository's suite convention.
  - Its header shows the repository's standard local docker-exec invocation.
  - It never commits; it was run against NemrynS1Iso in this phase.
  - No production command line exists for it.
  - Even a mistaken run against a local stack leaves no data, because of the rollback.
