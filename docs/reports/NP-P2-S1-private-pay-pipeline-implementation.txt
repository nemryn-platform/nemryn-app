5. STAGE MACHINE AND TERMINAL-STATE RULES
======================================================================
- Created in new_inquiry.
- OPEN stages: new_inquiry, contacted, qualified, quote_sent, quote_accepted.
  - plus_change_opportunity_stage moves an open opportunity to ANY other open stage: forward skips and backward moves
    are both allowed (product spec 4.3).
  - The same stage gives changed = false (no history row).
- LOST (terminal): only via plus_mark_opportunity_lost, with a required reason from the closed set. `other` requires
  a note. Already lost gives changed = false. Change stage / edit while lost gives ZW004.
- REOPEN: only via plus_reopen_opportunity, from lost, with a required reason (3-500) and an open target stage. It
  clears the lost fields and closed_at. Not lost gives ZW004; stale gives ZW003, so a duplicate reopen is never
  applied twice.
- CONVERTED (terminal): RESERVED.
  - No P2-S1 function can set it. Change stage refuses it (ZW006), and a source scan proves no Plus function assigns
    it (SQL T7).
  - Only the later P2-S4 Core conversion RPC may set it. No Convert control exists anywhere in the UI (E2E B7, N2).
- quote_sent / quote_accepted: STAFF-REPORTED sales stages. The UI labels them "Quote sent (reported)" /
  "Quote accepted (reported)" with "Nemryn hasn't created, sent or received a quote." No quote record, table or
  document exists (SQL T8; no plus_quotes table).
- Lost-reason closed set: the OWNER-APPROVED CANONICAL VOCABULARY, aligned in NP-P2-S1-R1A:
    no_response, price, chose_competitor, outside_service_area, service_not_offered, no_availability, not_a_fit,
    duplicate, other.
  All are non-medical. The draft set first used here was replaced before any commit (see NP-P2-S1-R1A).

6. RPC INVENTORY
======================================================================
Every RPC is SECURITY DEFINER with search_path pinned to (public, pg_temp), authenticated EXECUTE only, with ZW codes
per mutation-api.md. Organization binding comes from the server session.

Read (plus_can_read; ZW002 without access, ZW001 without a uid):
  - plus_list_opportunities(org, search, view, stage, source, owner_membership_id, contact_id, limit, offset)
    - view: open (default), lost, converted or all; search covers the title and the contact name (wildcards
      literal); 1-200 rows; most recently updated first;
    - returns the contact's name, status and do-not-contact flag; a foreign owner handle matches nothing.
  - plus_get_opportunity(org, id): ZW002 for a foreign or unknown id (no existence oracle).
  - plus_list_opportunity_activities(org, id, limit, offset): stage / owner history.
Write (_require_plus_write: ZW002 when the caller cannot read, ZW001 when they can read but not write):
  - plus_create_opportunity(...):
    - the contact must be an ACTIVE contact of the organization (archived ZW006; foreign / unknown / NULL ZW002), and
      is locked FOR NO KEY UPDATE, so creation serializes with an archive;
    - a 30-second duplicate-submission guard;
    - audit: plus_opportunity_created (no contact data).
  - plus_update_opportunity(..., expected_updated_at, ...):
    - open only; FOR UPDATE then version check (ZW003);
    - a new contact must be active; a new owner must be eligible; an unchanged ineligible owner is kept;
    - an owner change writes an owner_changed activity;
    - audit: plus_opportunity_updated, with field NAMES only.
  - plus_change_opportunity_stage, plus_mark_opportunity_lost, plus_reopen_opportunity: section 5.
Internal: _plus_require_active_contact, _plus_opportunity_channel_immutable.
Not implemented, by design: conversion, Request / Passenger / Trip / Recurring Care creation, request attribution,
and Core status synchronization.
