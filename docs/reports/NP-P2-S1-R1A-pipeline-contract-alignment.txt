2. STAGE-RULE CONFIRMATION (implementation decisions; no P2-S4 expansion)
======================================================================
Each rule was confirmed against code and tests:
  - Forward AND backward moves among the open stages are permitted. plus_change_opportunity_stage accepts any other
    open stage. (SQL T1 forward skip, T2 backward; E2E D3 / D5.)
  - Lost requires a reason, from the canonical set; `other` requires a note. (SQL L1, L11 / L12; E2E F0-F2b.)
  - Reopening Lost requires an explicit reason (3-500) and an open target stage. (SQL L6-L9; E2E F5 / F6;
    CONC-O3.)
  - Converted cannot be set manually.
    - Change stage refuses it with ZW006.
    - No Plus function assigns it (source scan T7).
    - The UI never offers it and shows no Convert control. (SQL T4 / T7; E2E D1 / B7 / N2.)
  - Archiving a contact does not delete or automatically close its opportunities. They stay open and workable, with
    an "archived contact" notice. (SQL H5; E2E M1.)
  - New opportunities cannot be created for archived contacts (ZW006), and an opportunity cannot be switched to one.
    (SQL C4 / U5 / H5; E2E M2; CONC-O6.)
These are now recorded as implementation decisions in plus-domain-model.md (section 8.1 notes). In the P2-S1 report,
D1, D2 and D3 are marked RESOLVED.
