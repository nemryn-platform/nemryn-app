5. KNOWN LOCAL BUILD LIMITATION — ROOT CAUSE FOUND
--------------------------------------------------
- Symptom (since 2026-10-20): the local default `next build` failed with 12 errors, "Module not found: Can't resolve
  '@vercel/turbopack-next/internal/font/google/font' … next/font/google queries have exactly one entry" (Geist Mono
  font CSS).
- This pass, on the final tree with the existing cache: still FAILED identically (TURBOPACK_TREE_EXIT=1).
- Unchanged main: a `git archive` export of origin/main 8131f0f in a separate scratch directory.
  - First attempt invalid: Turbopack refused a symlinked node_modules ("points out of the filesystem root"). Not
    counted.
  - Valid attempt (an APFS-cloned node_modules, no symlink): main BUILDS SUCCESSFULLY with Turbopack.
- Root cause: a stale local Turbopack persistent cache in the repository directory, `.next/cache/turbopack` (737
  MB). The earlier "fails on main too" result came from in-place control builds that shared that cache.
- Fix applied: the cache was MOVED aside (not deleted) to the session scratchpad
  (p1b/qa2/final/turbopack-cache-backup). The default build of this exact final tree then succeeded, and QA2 strict
  passed 195 / 195 against it.
- No font package, dependency, Next.js version or build tooling was changed.
- Correction to earlier reports: the sidebar-scrollbar and integrated-review reports said the failure "also occurs on
  unchanged main". That was true only for in-place builds sharing the stale cache. Unchanged main builds correctly
  in a clean directory, and Vercel's builds were never affected.
- Recommendation: if it reappears locally, move .next/cache/turbopack aside before investigating anything else.
