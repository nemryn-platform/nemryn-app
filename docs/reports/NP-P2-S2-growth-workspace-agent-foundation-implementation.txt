8. GROWTH AGENT RULES (deterministic, explainable; database: _plus_agent_candidates)
======================================================================
Scope:
  - open private-pay opportunities (new_inquiry .. quote_accepted);
  - of an ACTIVE contact;
  - with NO open task on the opportunity or its contact (staff already have a follow-up planned).
Signals, first match wins:
  1. new_inquiry_waiting: stage new_inquiry; the stage was never changed; no note, call, email or meeting logged
     since creation; created more than 2 days ago.
  2. awaiting_response: the latest interaction is a LOGGED call or email; it is also the latest entry of any kind;
     it is older than 5 days. The text says plainly that this does NOT mean the person ignored it, only that no
     reply was logged.
  3. no_recent_activity: nothing recorded on the opportunity or its contact for 10 days.
Explanation: signal_days, last recorded activity type and time, plus who ran the review, all shown on the card.
Dedupe:
  - condition_key = type:stage:last_activity_id;
  - an unchanged situation is never recommended twice, whatever its review outcome;
  - at most one pending recommendation per opportunity.
Supersede: a pending recommendation whose situation no longer matches is withdrawn ('superseded') by the next
review or by an approval attempt.
Thresholds:
  - the values above are INTERNAL-TEST values, shown to staff on the agent page, and NOT approved production policy;
  - changing them is a reviewed migration;
  - the example Day 3 / Day 7 / Day 14 cadence was NOT adopted.
Overdue tasks are deliberately not an agent signal: the dashboard already covers them, and a task-on-a-task would
duplicate work.
Trigger: staff click "Review opportunities" (dashboard or /operations/growth/agent). There is no scheduler, cron,
pg_cron or background job. generation_source accepts only 'staff_review'.

9. APPROVE / REJECT
======================================================================
plus_approve_agent_recommendation(org, rec, expected, task_title, due_at, assignee):
  - Locks the recommendation FOR UPDATE, then:
    - already approved: outcome already_approved with the SAME task (replay-safe; no second task);
    - superseded: a superseded no-op;
    - dismissed or not_relevant: ZW004;
    - stale token: ZW003.
  - REVALIDATION: re-runs the detection for that one opportunity. If the situation changed (an activity was
    logged, a task was added, the stage moved, the contact was archived), the recommendation is superseded and NO
    task is created. The UI says "out of date ... withdrawn. No task was created."
  - Otherwise it creates ONE open internal task on the opportunity via _plus_insert_task:
    - the staff-edited title, due date/time (workspace timezone) and eligible assignee;
    - it records reviewed_by, reviewed_at and approved_task_id, and audits plus_agent_recommendation_approved.
  - It never changes a stage, marks lost, writes an activity or a Core row, or sends anything.
plus_dismiss_agent_recommendation: 'dismissed' or 'not_relevant'.
  - Records the reviewer and time.
  - The same outcome again gives changed=false; a different outcome after review gives ZW004; stale gives ZW003.
  - A dismissed situation is not re-recommended while unchanged.
Concurrency:
  - simultaneous approvals: exactly one task (CONC-G1);
  - simultaneous reviews: serialized by the advisory lock (CONC-G2);
  - approve vs dismiss: exactly one outcome (CONC-G3).

16. LIMITATIONS
======================================================================
  - The task subject picker on the Tasks page offers open opportunities plus the first 25 active contacts. Any
    contact can still get a task from its own detail page. A searchable picker is a follow-up.
  - Lists cap at 100 tasks per view (TASKS_PAGE_SIZE) and the pipeline at 200; there is no pagination UI yet.
  - Overdue tasks are not an agent signal (by design; see section 8).
  - Consent is always "unknown" before P2-S6, so every draft carries the no-consent caveat. Drafts are copy aids
    only.
  - A grant revoked while a write is in flight is decided by the database at commit time. The UI shows the refusal
    on the next action; there is no live push.
  - Reviews run only when staff ask. There are no reminders and no scheduler (NP-P4 scope).
  - The Dashboard has no period filter, conversion, booking or quote figures (P2-S3/S4/S5/S8).
  - Draft text edits are deliberately not saved; a reload restores the template.

17. DECISIONS (taken within the brief; flagged for owner review)
======================================================================
  D1. "Dashboard" is the child label for /operations/growth, which is the Growth Overview. The Agent page lives under
      it in navigation terms.
  D2. Tasks never write plus_activities (no duplicate history). Task history is the task row plus audit_events.
  D3. A date-only due date means 23:59 in the workspace timezone; "today" is the workspace day.
  D4. Agent thresholds are internal-test values 2 / 5 / 10 days, plus a suggested due date 1 day out. They are
      shown to staff and NOT production policy.
  D5. The agent proposes ONLY internal follow-up tasks (CHECK-enforced). Any other proposal type needs a reviewed
      migration.
  D6. Approval revalidates and withdraws stale recommendations instead of creating tasks for them.
  D7. An opportunity with ANY open task (on it or its contact) is not flagged: staff already have a plan.
  D8. Drafts come from a local template only. No provider integration; the seam is GrowthAgentDraftProvider.
