2. D-1 — CAUSE AND SOLUTION
======================================================================================================================
Cause
  getTripDetail() (src/lib/operations/trip-detail.ts) took driver and vehicle only from the ACTIVE assignment
  (ended_at IS NULL). Completing a trip ends its assignment (ended_at set, row kept as history), so a completed trip had
  no active assignment and the summary strip showed "Driver: Unassigned / Vehicle: —". Data was intact (Proof of
  Service already showed the driver and vehicle).

Solution (smallest safe change)
  - New pure helper displayAssignmentOf(assignments, tripState, organizationId):
      * any trip with an active assignment -> that assignment (existing behaviour, unchanged);
      * a COMPLETED trip with no active assignment -> the most recently ended assignment (latest ended_at; ties ->
        latest assigned_at), i.e. who actually drove — after a reassignment, the final driver;
      * cancelled / no-show / scheduled-without-assignment / no or unreadable history -> none (placeholders stay);
      * rows of another organization are ignored (defence in depth; the query already joins assignments on
        (trip_id, organization_id) under the caller's RLS, and the trip itself is filtered by organization).
  - Only the summary strip's Driver / Vehicle facts use it (summaryDriverName / summaryVehicleLabel).
    activeAssignmentId, driverId, vehicleId, driverName, driverPhone and vehicleLabel are unchanged, so assignment /
    reassignment controls, overlap checks, the Current Status panel, the action bar and the status label behave exactly
    as before. No extra query (organization_id added to the existing embed).
