11. ASPECT-RATIO FINDINGS
====================================================================

  Current Zenward auth-logo frame: `width={240} height={80}`,
  `className="h-auto w-60"` → ratio **3.000** (240/80).

  `nemryn-logo-inverse.svg` real geometry: `viewBox="0 0 434 127"` →
  ratio **3.4173** (434/127).

  `nemryn-wordmark-primary.svg` alone: `viewBox="0 0 301 84"` → ratio
  **3.5833**.

  `nemryn-symbol-primary.svg` alone: `viewBox="0 0 128 139"` → ratio
  **0.9209** — nearly square, TALLER than wide (the symbol alone is a
  compact mark, not a wide lockup shape).

  `OperationsSidebar`'s current frame: `width={217} height={72}` →
  ratio **3.0139** — essentially the same as the auth frame's 3.000.

  `onboarding/layout.tsx`'s current frame: `width={160} height={53}`
  → ratio **3.0189** — also essentially the same.

**Finding: the Nemryn full-lockup geometry (3.417) is measurably WIDER
relative to its height than every current Zenward logo frame (~3.00–
3.02).** Forcing the Nemryn artwork into a fixed 240×80 (or 217×72, or
160×53) box — i.e. supplying BOTH an explicit width AND an explicit
height that don't match its own 3.417 ratio — would VISIBLY SQUASH the
mark, directly violating the README's own explicit "Do not stretch...
alter proportions" rule and this work item's own "Never distort the
Nemryn artwork to preserve the old Zenward dimensions" instruction.

**Correct future sizing approach (not implemented in this phase):**
supply only ONE explicit dimension (either width or height) at each
call site, let the other dimension follow the artwork's own intrinsic
ratio (e.g. via `height="auto"`/`width="auto"` in combination with
Next.js `Image`'s own `width`+`height` props computed FROM the real
434:127 ratio, not copied from the old 240:80 pair) — "the UI must
adapt to the logo," exactly as instructed, never the reverse.
