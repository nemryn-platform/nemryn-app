5. ELIGIBLE REQUEST DEFINITION
------------------------------------
`getNewTripFormData`'s request query (§5 of the phase spec) now
requires, in addition to the pre-existing `state in ('pending',
'accepted')`: `passenger_id IS NOT NULL` AND the linked Passenger's
own `status = 'active'`. Implemented by embedding
`passengers!transportation_requests_passenger_id_organization_id_fkey
(display_name, status)` (the explicit FK-name hint is required — this
table carries two foreign keys to `passengers`, P1-E1-S2D §32 — an
unqualified embed is ambiguous to PostgREST) and filtering in
application code after fetch (`passenger_id !== null && passenger
.status === "active"`), not via a PostgREST `!inner`-embed filter —
this list is small and org-bounded, so a plain post-fetch filter
avoids relying on embedded-relation filter syntax for something this
simple; documented as a deliberate choice, not an oversight. Excludes
exactly the four cases §5 lists: unresolved pending, inactive-
Passenger pending, inactive-Passenger accepted, declined, cancelled.
No Request row is ever mutated merely to make it eligible — this is a
read-side filter only.

7. REQUEST/PASSENGER BINDING
---------------------------------
`NewTripForm`'s state model changed from one `passengerId` state
variable to two: `manualPassengerId` (used only in direct-Trip mode)
and a derived, ALWAYS-fresh `effectivePassengerId = selectedRequest ?
selectedRequest.passengerId : manualPassengerId` — the ONE value ever
actually submitted (the hidden `passengerId` input always renders
`effectivePassengerId`). This structurally guarantees the Passenger
can never diverge from a selected Request's own resolved Passenger —
there is no code path where the two could be set independently while
a Request is selected. When `selectedRequest` is truthy: the Passenger
section renders a read-only card ("{name} / Linked from transportation
request"), no `Combobox`, no "Add New Passenger" button (the
`FormSection`'s `action` prop itself is conditionally omitted, not
merely visually hidden) — live-verified the operator cannot reach an
editable Passenger control of any kind while request-linked.

9. REQUESTID QUERY PARAM
-----------------------------
`/operations/trips/new?requestId=<uuid>` is resolved with ZERO
additional queries: `requestedId ? requests.find(r => r.id ===
requestedId) ?? null : null` against the SAME already-fetched,
already org-scoped, already eligibility-filtered `requests` array the
page renders its own dropdown from. A malformed id, a nonexistent id,
a foreign-org id, and a currently-ineligible id all produce the
IDENTICAL "not found in this list" outcome — never distinguished from
one another, no existence oracle of any kind, and no raw UUID-cast
error risk (the malformed string is never sent into a new Supabase
query at all). `requestUnavailable` (true only when a requestId was
supplied but not found) renders the restrained, exact copy specified:
"Selected request is unavailable for trip creation." — followed by
"Continue below to create this trip directly, or choose a different
request." — never explaining why.


10. PRESELECTION
---------------------
A valid, eligible `requestId` preselects that Request (`useState(() =>
preselectedRequestId ?? "")` for `requestId`), binds its Passenger

route originates from Request Detail, the form ALSO auto-initializes

timestamp conversion happens here — `preferredDate`/`preferredTime`
are copied as plain strings into the form's own local date/time
inputs exactly as "Import request details" already did; the real
organization-timezone conversion remains the one existing boundary in
`createTripAction`, untouched. (Implementation note: the FIRST attempt
used a `useEffect` calling several `setState` functions on mount,
which `eslint-plugin-react-hooks`'s `set-state-in-effect` rule
correctly flagged as a real anti-pattern — fixed by switching to lazy
`useState(() => ...)` initializers instead, the idiomatic React fix
for "initialize from a prop once," with zero behavioral difference.)

17. FORGED-MISMATCH PROTECTION (EXACT DEFENSE LAYERS)
-------------------------------------------------------------
Two independent layers, both confirmed live, not merely asserted:
  Layer 1 (application, new this phase): when `requestId` is present
    in the submitted FormData, `createTripAction` performs one small,
    org-scoped lookup (`select passenger_id from
    transportation_requests where id = requestId and organization_id
    = organization.organizationId`) and uses THAT Request's own
    `passenger_id` as `p_passenger_id` — the client's own submitted
    `passengerId` field is IGNORED whenever this lookup succeeds. If
    the lookup finds nothing (malformed/nonexistent/foreign-org/stale
    requestId), no override is applied and the original client value
    passes through — `create_trip`'s own existing `not found` check on
    `p_request_id` still authoritatively rejects the whole call
    regardless, so the final security posture is unchanged either way;
    this lookup only ever narrows what reaches the RPC, never widens
    it. No new query architecture — one `.select()` call.
  Layer 2 (database, S2F-A, unchanged): `create_trip`'s own hardened
    `is distinct from` check remains the final, mandatory enforcement
    boundary regardless of what the application layer does.
Live-verified end to end with a REAL forged submission (not a
simulated/mocked one): navigated to the preselected New Trip route,
then used a genuine DOM property-setter to overwrite the hidden
`passengerId` input's value to a DIFFERENT, valid, same-org, active
Passenger than the selected Request's own — simulating a tampered
client exactly as a malicious browser extension or modified request
might. Submitted the form. Result: Trip creation SUCCEEDED (proving
Layer 1 silently and correctly ignored the forged value, rather than
the whole submission failing), and the created Trip's own Detail page
confirmed the Passenger was the REQUEST's real, correct Passenger —
the forged one never reached the database at all. This is the
strongest possible proof of Layer 1's real effect, not just its
presence in the source.

Four live-test-SCRIPT bugs were found and fixed during this phase's
own testing (all confirmed as test-script issues via direct DOM/value
inspection before being corrected — none was a product defect):
  1. Checking `document.body.innerText` for a `<textarea>`/`<input>`'s
     VALUE (auto-import verification) — `innerText` never reflects
     form-control values; fixed by reading `.value` directly.
  2. Checking `document.body.innerText` for a `<Combobox>`'s
     `placeholder` attribute — placeholders are not part of
     `innerText`; fixed by inspecting the real DOM element and its
     `.disabled` property.
  3. An overly broad regex (`/organization|.../i`) flagged this
     phase's own genuine "unavailable" notice as a suspected leak,
     because the SAME page separately, legitimately, and unrelatedly
     contains the word "organization" in pre-existing Trip Schedule
     copy ("times are in the organization's timezone") — fixed by
     scoping the check to the notice's own DOM subtree.
  4. Returning a raw DOM element reference from a CDP `Runtime.
     evaluate` call with `returnByValue: true` produced a genuine CDP
     protocol error ("Object reference chain is too long" — DOM nodes
     carry large circular object graphs that don't serialize safely)
     — fixed by coercing to a boolean inside the evaluated expression
     itself.
  5. (Regression suite) Two of S2E's OWN pre-existing test assertions
     used `a.href.includes('/operations/trips/')` to find a linked
     Trip's row link — this phase's new "Create Trip"/"Create Another
     Trip" link (`/operations/trips/new?requestId=...`) also contains
     that substring and, appearing earlier in the DOM (header, before
     the Linked Trips panel), was matched first — fixed by excluding
     `/operations/trips/new` from those two pre-existing selectors.
Every one of these was independently confirmed as a test-script issue
(via targeted debug scripts reading real DOM state) BEFORE being
"fixed" — no product behavior was ever changed to make a test pass.
