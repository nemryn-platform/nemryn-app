4. FINDING (reported separately; NOT fixed here)
------------------------------------------------
F-1. Dispatch grid scroll container is not keyboard-focusable when no trips are on the grid.
- axe "scrollable-region-focusable" (serious), WCAG 2.1.1.
- Production state: 3 drivers, 0 trips today. The horizontally scrollable grid ([data-testid="dispatch-grid"],
  overflow-x: auto) contains no focusable element, so a keyboard user cannot scroll it.
- Pre-existing, NOT introduced by P2:
  - the grid's overflow container dates from P1-E3-S5;
  - P2 changed only its width / raise.
  - It went undetected because every isolated suite had trips on the grid (trip blocks are focusable buttons).
- Impact: low. An empty grid has no actions to reach; the only thing a keyboard user can't do is scroll to see later
  empty hours.
- Proposed fix (needs approval):
  - give the grid container tabIndex={0}, role="region" and aria-label="Today's assignments schedule" (a focusable,
    named, keyboard-scrollable region);
  - add a QA2 check for "drivers but no trips" (the coverage gap).
