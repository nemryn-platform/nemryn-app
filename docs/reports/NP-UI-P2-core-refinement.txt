------------------

  one-item summary strip) and the search, with a live result count.
- Refined table; shared Pagination.
- Detail panels are raised. Log Request field groups use the shared card anatomy.
- Status rules, decisions and the handoff are unchanged.

B. Trips:

- New Trip field groups (FormSection) get the card anatomy: icon tile, hairline, fields.
- Trip Detail panels are raised.
- Lifecycle, scheduling and assignment are unchanged.

C. Dispatch:
- The Today / Tomorrow ViewSwitch.
- A raised summary with prominent tabular values; the amber tone only when something is unassigned.
- Column headers in PanelHeader anatomy; denser queue cards with the pickup time first; compact empty states.
- Grid legibility: below 2xl the capacity rail moves under the board, so the time grid gets the full width (at
  1440: about 6 AM–4 PM visible, was 6 AM–11 AM). The grid still scrolls inside its own container.
- Assignment logic and the data-trip-id hooks are unchanged.

D. Tomorrow Readiness:
- The title is "Tomorrow Readiness"; "Open in Dispatch" is the header action (data-testid kept).
- Real StatTiles: scheduled (→ the Dispatch tomorrow board), ready, need preparation (→ the list anchor).
- Needs preparation / Ready in the card rhythm with a time column, reason badges, Assign / Add vehicle / View trip
  actions unchanged.

E. Related surfaces:
- Standing Orders:
  - the "Standing Orders" title and breadcrumbs, a FilterBar, a raised table;
  - the detail page gains the compact "Standing Order" h1 (fixes the QA2 baseline defect);
  - the Brief and request-panel copy read "Standing orders".
- Passengers: FilterBar + result count.
- Facilities / Vehicles / Drivers: one PageHeader with the primary action in it (Add Facility / Add Vehicle /
  Invite Driver; the same role gating). The title is "Vehicles", not "Fleet".
- Proof of Service: the ViewSwitch window in a FilterBar with a count; shared Pagination.
- No feature redesign. Nothing needed new interaction architecture.
