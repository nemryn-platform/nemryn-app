2. TASK SCHEMA CONFIRMATION (BEFORE ANY CHANGE) — NO CHANGE REQUIRED
======================================================================
I checked migration 20261015100000_plus_tasks.sql against ZD-225:
- Opportunity subject: plus_tasks.opportunity_id has a composite FK (opportunity_id, organization_id). The
  CHECK num_nonnulls(contact_id, opportunity_id) = 1 means an opportunity-only task is valid.
  plus_create_task -> _plus_require_task_subject accepts an OPEN opportunity of the same organization. After Mark
  sent, the opportunity is still open, so a follow-up can be created.
- No default due date: due_at is nullable, and plus_create_task accepts p_due_at NULL.
- Default assignee = the person who marked the quote sent: _plus_resolve_owner accepts any eligible Plus writer's
  membership handle. Mark sent itself needs Plus write, so the sender is always eligible.
- Duplicate guard: plus_create_task already treats the same open title, by the same person, for the same subject
  within 30 seconds as an idempotent no-op, serialized by the subject row lock. Together with the dialog's
  single-submit guard and the open-task notice, this meets Q11.5 Option A.
- No automatic changes: the quote lifecycle RPCs (plus_mark_quote_sent, plus_record_quote_response,
  plus_revise_quote, plus_withdraw_quote) never reference plus_tasks. A unit test asserts this over every
  plus_quote* migration.
Conclusion: no migration, no new column (no quote_id on tasks), and no RPC change. The existing TaskDialog,
createTaskAction and plus_create_task are reused as they are.

A. Printable view (ZD-224)
- New route: src/app/quote-print/[quoteId]/page.tsx. It sits outside /operations (no shell), like /day-sheet.
  - Guard: requirePlusAccess. That means a signed-in staff member of the current workspace with Plus READ or above,
    and it runs before any read.
  - isUuid check; plus_get_quote runs on the per-request cookie client, never the service role.
  - Unknown, foreign and malformed ids all give the same notFound().
  - force-dynamic (the response is "private, no-cache, no-store"); robots noindex.
  - No generateStaticParams, no public segment, no token.
- Content comes from the pure model quotePrintModel() in src/lib/plus/quotes-core.ts:
  - the organization name (session workspace) and its EXISTING business phone / email / address, read via
    getOrganizationSettings with member RLS;
  - the customer's display name only;
  - the kind and "Estimate N" / "Quote N";
  - date, valid until, shared date, service, round trip and miles;
  - the non-zero itemized charges (quoteChargeLines), the discount, and the STORED total_cents in USD (never
    recalculated);
  - the terms note;
  - the footer "This is a quote / an estimate, not an invoice. Prices in US dollars."
  It does not print: contact phone / email, the opportunity title, staff names, the withdrawal reason,
  addresses / appointments / medical information, branding or logo.
- Status labels and banners:

  | Status            | Label      | Banner                                              |
  |-------------------|------------|-----------------------------------------------------|
  | Draft             | Draft      | DRAFT — not yet given to the customer               |
  | Sent              | Sent       | none                                                |
  | Sent, past date   | Expired    | EXPIRED (derived), with the passed date             |
  | Accepted          | Accepted   | ACCEPTED — "recorded by staff on <date>"            |
  | Declined          | Declined   | DECLINED — "recorded by staff on <date>"            |
  | Superseded        | Superseded | SUPERSEDED — "Replaced by Quote N …"                |
  | Withdrawn         | Withdrawn  | WITHDRAWN — "No longer offered."                    |

  The in-app panel labels are unchanged (canonical UI preserved).
- Toolbar src/components/growth/QuotePrintToolbar.tsx: screen-only (print:hidden), with "Print / Save PDF"
  (window.print) and "← Back to the opportunity", plus a note that the PDF is the team's own copy. There is no
  email, share, mailto, SMS or upload.
- Entry points: a "Print" link (new tab, rel=noopener, with screen-reader text) on every quote row of the Opportunity
  panel (current and history) and on every directory row. The directory link stops propagation, so the row
  navigation doesn't also fire.
- Read model: QuoteDetail gains opportunityId and contactName. These are fields plus_get_quote already returned, so
  the database is unchanged.

- TaskDialog gains one optional `notice` prop, rendered above the fields. It is additive; other callers are
  unchanged.
