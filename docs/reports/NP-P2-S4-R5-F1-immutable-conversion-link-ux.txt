1. PROBLEM (from R5)
======================================================================
- On a Request created by "Create transportation request", the Request detail Growth panel still offered "Correct
  link".
- The database already refuses any change to a conversion link (plus_update_request_attribution: ZW004
  conversion_link_immutable).
- But the UI mapped every ZW004 to "This request is already linked in Growth. Use 'Correct link' to change it.", a
  misleading message.

2. CHANGE (UI and message mapping only)
======================================================================
1. src/lib/plus/attribution-core.ts
   - isLinkCorrectable(linkMethod): false only for converted_from_opportunity. linked_existing_request and rebooking
     stay correctable, exactly as before.
   - CONVERSION_LINK_NOTE = "This request was created from this opportunity, so the link can't be changed."
   - CONVERSION_LINK_IMMUTABLE_MESSAGE = "A request created from an opportunity stays linked to it."
   - attributionErrorMessage(code, reason?): ZW004 with reason conversion_link_immutable -> the message above. Every
     other ZW004, and every other code, keeps its existing message. The reason only refines ZW004.
2. src/components/growth/RequestGrowthPanel.tsx
   - For a conversion link, the panel renders the permanence note (data-testid request-growth-conversion-note)
     INSTEAD OF the write controls.
   - The note shows for every Growth viewer, including read-only, since it is informational.
   - Contact, opportunity (with its stage, "Converted") and "Link: Created from an opportunity by <staff>, <time>" are
     displayed unchanged, with working links.
   - Manual and rebooking links keep "Correct link" for writers, as before. The unlinked state keeps "Track in Plus".
3. src/app/operations/growth/attribution/actions.ts
   - correctAttributionAction passes the database's reason: attributionErrorMessage(error?.code, error?.message).
     That keeps the message right even if a stale page or a direct POST attempts a conversion-link correction.
   - Authorization, validation and the RPC call are unchanged.
4. src/lib/plus/attribution-core.test.mjs: 3 new unit tests (section 4).

Unchanged:
- every RPC, migration, grant and RLS rule; the database safeguards;
- the conversion and rebooking workflow (booking actions, dialog, retry key, OD-6 notice);
- RequestGrowthControls.tsx;
