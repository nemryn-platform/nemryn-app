4. RPC
======================================================================
  record_trip_completion_by_operations(p_trip_id uuid, p_expected_current_state text, p_completed_at timestamptz,
                                       p_note text) returns public.trip_transition_result
    (trip_id, previous_state, current_state, changed -- the existing result type).
  SECURITY DEFINER; search_path = public, pg_temp; PUBLIC / anon no EXECUTE; authenticated EXECUTE; single overload.
  Order of checks (all inside one transaction):
    1. auth.uid() null -> ZW001.
    2. Trip row locked FOR UPDATE; not found OR caller lacks has_org_role(trip org, [organization_admin, dispatcher])
       -> ZW002 (identical for every denial -- no existence oracle).
    3. state <> p_expected_current_state (or null expected) -> ZW003 stale_state.
    4. state not in (passenger_onboard, en_route_to_destination, arrived_at_destination) -> ZW004.
    5. active assignment locked FOR UPDATE; none -> ZW006 (integrity problem; never created or reconstructed).
    6. note trimmed, 10..500 -> else ZW006.
    7. p_completed_at null, or > now() + 5 minutes, or < max(occurred_at) of the existing lifecycle events
       (en_route_to_pickup .. arrived_at_destination) -> ZW006. Never inferred server-side.

5. AUTHORIZATION
======================================================================
  Allowed: Organization Admin, Dispatcher of the Trip's organization.
  Denied (ZW002): any Driver including the assigned Driver; foreign tenant; inactive membership; suspended
  organization; no membership; Platform Admin without membership; nonexistent Trip. Anon: permission denied.
  The Trip Detail page is already Organization Admin / Dispatcher only (requireOperationsAccess; Drivers are
  redirected to /driver); the Server Action re-derives access on every call.

======================================================================
6. ELIGIBLE / INELIGIBLE STATES
======================================================================
  Eligible: passenger_onboard, en_route_to_destination, arrived_at_destination (owner decision D-6).
  Ineligible: scheduled, en_route_to_pickup, arrived_at_pickup (reassign / no-show / cancel remain their paths) and
  completed, cancelled, no_show (terminal). No idempotent no-op: a completed Trip is ZW004 (or ZW003 with a stale
  expected state).

======================================================================
7. ACTIVE-ASSIGNMENT RULE / ASSIGNMENT CLOSURE
======================================================================
  - Required. Missing -> ZW006, Trip untouched, nothing created (SQL C22).
  - On success the active row is closed IN PLACE: ended_at = now(), end_reason = 'trip_completed' -- the same
    end_reason the Driver's own completion writes (the assigned Driver did perform the ride). Earlier rows (e.g.
    'reassigned') are untouched; nothing deleted or re-pointed (SQL C26).
  - Consequence: every existing reader keyed on end_reason = 'trip_completed' (Proof completion assignment,
    recurring "who drove last time" hints, driver history) treats the recovered Trip truthfully without change.

======================================================================
8. COMPLETION TIME / REQUIRED NOTE
======================================================================
  Time: operator-stated, organization-local in the UI (default = current org-local time), converted with the same
  DST-honest organizationLocalToUtc as Edit Trip (nonexistent / ambiguous -> refused). DB bounds: <= now + 5 min;
  >= latest existing lifecycle event; required.
  Note: required, trimmed, 10..500 characters. UI helper: "Say how completion was confirmed. Don't include health
  information." No keyword scanning. Stored ONLY in audit_events.reason.

======================================================================
9. AUDIT MODEL / TRIP-EVENTS MODEL
======================================================================
  audit_events (Organization Admin readable only): action trip_completion_recorded_by_operations; entity trip;
    actor = the operator; before_data {state}; after_data {state: completed, completed_at}; reason = the trimmed note.
  trip_events: exactly ONE completion_recorded_by_operations; actor_user_id = the operator; occurred_at = now()
    (when it was recorded); metadata = {previous_state, recorded_completed_at, note_present: true} -- exactly these
    three keys, never the note (SQL C1 checks the key set; E2E C4 checks the text).

======================================================================
10. NO-FABRICATION SEMANTICS
======================================================================
  Never written: trip_completed; any skipped en_route_to_destination / arrived_at_destination; any edit or delete of
  an existing event or timestamp. Recovery from passenger_onboard leaves exactly en_route_to_pickup,
  arrived_at_pickup, passenger_onboard + completion_recorded_by_operations (SQL C25; E2E C3). Historical
  incompleteness is preserved rather than filled in.
