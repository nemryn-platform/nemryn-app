  | idempotency_key | ^[A-Za-z0-9._:-]{8,200}$ |

8. PRICING ARITHMETIC AND VALIDATION
======================================================================
- Money arrives as bigint cents. The SQL signature makes fractional cents impossible: a 12.5 or '12.50' argument is not
  a valid call (suite C8). No float or real type is used anywhere.
- NULL money inputs mean 0. NULL distance means none.
- _plus_quote_validate computes subtotal = the eight charges, and total = subtotal − discount. The server computes the
  total, and the RPCs have no total parameter. The CHECK re-verifies the identity on every row (suite C15: a forged
  total → check_violation).
- Refused with ZW006:

  | Input | Refused when |
  |---|---|
  | Each charge | < 0 or > 10,000,000 ($100,000.00); exactly 10,000,000 is accepted (C7) |
  | Discount | < 0, > 10,000,000, or > subtotal, so the total is never negative (C5) |
  | Distance | < 0, > 99,999.9, or more than one decimal; never rounded (C9) |
  | other_label | without other_cents, or other_cents without a label, or more than 60 characters (C10) |
  | Kind and service | kind not estimate | quote; a service outside the 8 Plus services, including airport_transportation and case variants (C11) |
  | Terms and validity | terms over 500 characters; valid_until NULL or before the organization-local today (C12) |

- "Today" is _plus_org_local_today(org) = (now() at time zone organizations.timezone)::date. timezone is NOT NULL and
  IANA-validated.
- USD only: there is no currency parameter, and a CHECK rejects any other value (C16).
- Integer exactness: 333 + 333 + 334 = 1000 (C17); 27,300 − 1,250 = 26,050 (C1).

10. LIFECYCLE TRANSITIONS
======================================================================
| From | Action | To | Conditions and effects |
|---|---|---|---|
| (none) | create | draft | open opportunity; active contact; valid snapshot; number allocated; audit plus_quote_created |
| draft | update draft | draft | not stale (ZW003); identical payload → changed=false, no write, no audit; audit plus_quote_draft_updated |
| draft | mark sent | sent | not stale; valid_until ≥ today (else ZW004 quote_expired); a revision's predecessor must still be sent (else ZW004 revision_base_not_current) and is superseded in the same transaction; stage advance (§11); audit plus_quote_sent (+ plus_quote_superseded) |
| draft | withdraw | withdrawn | reason optional; audit plus_quote_withdrawn |
| sent | record accepted / declined | accepted / declined | not stale; not expired (ZW004 quote_expired); accepted advances the stage; audit plus_quote_accepted / plus_quote_declined |
| sent | revise | (new draft) | at most one live successor (ZW004 revision_exists); also allowed when expired; the source is unchanged until the revision is sent |
| sent | (revision sent) | superseded | |
| sent | withdraw | withdrawn | reason required (ZW006); audit carries the reason |

Final statuses: accepted, declined, superseded, withdrawn. Every further action raises ZW004 illegal_transition, except
the idempotent repeats listed below.

Idempotent repeats (changed=false, nothing written): Mark sent on a sent quote; the same response again; withdraw on a
withdrawn quote; a replay of create or revise with the same key.

Expiry is DERIVED: is_expired = status = 'sent' AND valid_until < the organization-local today. There is no stored
status and no scheduler (L13–L15).

Any write on a quote of a converted or lost opportunity raises ZW004 opportunity_closed, including withdraw (L26,
L27). The quotes stay readable.

11. OPPORTUNITY STAGE INTERACTIONS
======================================================================
_plus_quote_advance_stage(opportunity, target) runs only inside Mark sent and Record accepted, on an opportunity
already locked FOR UPDATE and verified open.
- Mark sent moves new_inquiry / contacted / qualified to quote_sent. quote_sent and quote_accepted are unchanged (L11).
- Record accepted moves new_inquiry / contacted / qualified / quote_sent to quote_accepted. quote_accepted is
  unchanged (L12).
- Declined never changes the stage and never marks the opportunity Lost (L10).
- A quote action never regresses a stage. converted and lost are refused before any write (ZW004 opportunity_closed).
  No quote action ever writes stage_changed to converted or lost (X3).
- Each real advance writes exactly ONE stage_changed activity (opportunity_id, from_stage, to_stage, actor), the same
  row a manual plus_change_opportunity_stage writes (L1). A repeated Mark sent writes no second row (L2).
- The stage advance bumps the opportunity's updated_at, so a concurrent stale opportunity write is refused (CONC-Q8b:
  Lost from the old version → ZW003).
- Upgrade rehearsal: a quote_accepted opportunity was then converted through the unchanged P2-S4 RPC. Results:
  - the Request carried the opportunity's dialysis service, in state pending;
  - the stage became converted;
  - the accepted quote stayed accepted / 28100;
  - quote writes on the converted opportunity were then refused.
- Quotes are NOT required for conversion (unchanged product rule).

12. NUMBERING AND IDEMPOTENCY
======================================================================
Numbering
- _plus_next_quote_number(org): insert … on conflict do nothing, then update … set next_number = next_number + 1
  returning next_number − 1.
- The row lock is held until commit, so concurrent creates serialize.
- The counter is transactional: a rolled-back create also rolls back its number. Numbers are unique per organization
  (unique constraint) and are never reused.
- Numbering is per organization: Org B starts at 1 independently (N1).
- CONC-Q3: six parallel creates got six distinct, consecutive numbers.
- No RPC deletes a quote. N1 shows that the owner deleting a fixture does not cause reuse.
- The display format is open (OD-Q10).

Idempotency (create and revise)
- The key is 8–200 characters of [A-Za-z0-9._:-] (_plus_require_idempotency_key) and is unique per organization.
- The advisory transaction lock is hashtext('plus-quote:' || org || ':' || key) and is taken before any read.
- Create replay: the same key on the same opportunity returns the ORIGINAL quote with changed=false. A different
  payload changes nothing (C3).
- The same key on another opportunity, or a key that belongs to a revision, raises ZW006 and never returns another
  quote (C4).
- Revise replay: the same key on the same source returns the same revision (L17).
- Authority is re-checked on every call, including replays. A key is never proof of access.
- CONC-Q1 / Q2 (a double click, and two staff with the same key) each produced one quote with outcomes t + f.

Optimistic concurrency: update, send, respond and withdraw compare p_expected_updated_at with the locked row, and
refuse with ZW003 on mismatch.

14. RLS AND TENANT-ISOLATION EVIDENCE
======================================================================
- plus_quotes has RLS on, exactly one policy (SELECT, plus_can_read(organization_id)), authenticated SELECT only, and no
  privilege for anon or service_role (S1–S3).
- plus_quote_counters has RLS on, no policy and no privilege for any client role (S1, S2, N2).
- RLS reads (A6):
  - Org B admin sees 0 Org A quote rows;
  - Org A admin sees Org A rows;
  - a Driver sees 0 rows.
- RPC isolation (A5): every lookup filters by (id, organization_id).
  - Org B admin on Org A ids gets ZW002.
  - Org A admin passing Org B's quote or opportunity under Org A gets ZW002.
  - A random uuid gets the identical response, so there is no existence oracle.
  - Mark sent and Revise on a foreign quote give ZW002.
- Composite FKs mean a quote cannot reference another organization's opportunity, and a revision cannot point across
  organizations or opportunities (L21).
- prevent_organization_id_change blocks a change of organization.
- plus_list_quotes with a foreign opportunity under the caller's own organization returns 0 rows (A11).
