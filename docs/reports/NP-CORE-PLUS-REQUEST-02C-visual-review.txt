4. ACCESSIBILITY FINDINGS (handoff section 3) — reported, not fixed
======================================================================================================================
  axe-core 4.10.2: 0 violations on the panel and on the whole page in all five required states: unlinked, form,
  validation errors, duplicate warning, linked.
  Keyboard: everything is operable; the Tab order matches the visual order; Enter submits; Cancel works by keyboard.

  A1  Focus is lost after Cancel (moderate; WCAG 2.4.3 Focus Order). Enter on Cancel unmounts the form, and focus
      falls to <body>. A keyboard or screen-reader user must Tab from the top of the page.
      Suggested change: return focus to the "Add contact" button.
  A2  Focus is lost after a validation error (moderate; WCAG 3.3.1 / 2.4.3). The form re-mounts so that it can keep
      the typed values, and that drops focus to <body>. The field error is linked by aria-describedby, but it is only
      read when the field gains focus, so a screen-reader user may not hear which field is wrong.
      Suggested change: focus the first invalid field after a refused submission.
  A3  Focus is lost after success (minor; WCAG 2.4.3). The form closes, and focus falls to <body>.
      Suggested change: move focus to the success notice (tabIndex -1) or to the new contact link.
  A4  Live regions are inserted with their content (minor; WCAG 4.1.3 Status Messages). The success notice
      (role="status") and errors (role="alert") are mounted at the moment they appear, not as regions that were
      already on the page. Browsers and screen readers usually announce a newly inserted role="alert", but often
      skip a newly inserted role="status". Combined with A3, the success may go unannounced. Pending has aria-busy
      on the button, but no spoken "Saving…".
      Suggested change: a persistent, initially empty role="status" region in the Growth panel that receives the
      success / pending text.
  Not done: a real screen-reader session (VoiceOver / NVDA). The checks above are structural. A manual VoiceOver pass
  on macOS Safari is recommended before release if A1–A4 are fixed. The same focus pattern (focus not restored)
  was the U2 finding in the quotes module, which was fixed there in NP-UI-P1a. A1–A3 could follow that approach.

5. OTHER OBSERVATIONS (no change made)
======================================================================================================================
  O1  After "Add contact", the Link row reads "Linked to an existing request by <name>, <date>"
      (05-success-*.png). The label comes from the released linkMethodLabel('linked_existing_request'), because the
      new function links through the released plus_link_request. It is accurate (the request existed before the
      link), but staff may read it as "an existing contact was linked". Possible copy: "Linked from Request Details".
      That is a display-only change, with no database change and no new link method.
  O2  "Open in Plus" sits next to the contact name, which links to the same contact (as in 02B). Kept as the explicit
      action the handoff asked for.
  O3  In a race, the losing session sees one of two correct messages, depending on timing:
        - "linked … by someone else just now … Reload the page" (an error, with the form kept open), or
        - "already linked, so no contact was added" (success, with the current link shown).
      Both are accurate. The first asks the person to reload, and the second refreshes by itself.
