1. ROOT CAUSE
-------------
The filter form was a single viewport-driven flex row:
  form: "flex flex-col gap-zw-md ... md:flex-row md:items-end"
  Search: "min-w-0 flex-1"   Status: "md:w-60" (240px fixed)   Sort: "md:w-56" (224px fixed)
  Apply / Clear: "flex gap-2"
Above the md breakpoint (768px VIEWPORT) every control sat on one row:
- Status, Sort and Apply / Clear had fixed or intrinsic widths;
- Search was the only shrinkable item, with min-w-0 (no floor).
The Operations content column is much narrower than the viewport, because of the sidebar and page padding. So at
tablet and laptop widths Search absorbed all the shortage and collapsed:
- down to 26px, the input's padding only;
- its "Search" label then overflowed onto the "Status" label (measured as label-text overlap = 1; visible in
  before-noresult-822.png).
Clear (shown whenever a search or status is active) took a further ~60px from Search, so filtered states collapsed at
wider widths than unfiltered ones.
This is the same defect class as the Pipeline (NP-UX-FILTER-01): the layout responded to the viewport, not to the space
the form actually has.

2. SOURCE CHANGES
-----------------
One file: src/app/operations/growth/quotes/page.tsx (+25 / −19; class names and one wrapper div only). This is the same
pattern as the approved Pipeline fix.
- The form becomes a CONTAINER (`@container`). The layout follows the form's own width, not the viewport, so the
  sidebar expanding or collapsing is handled correctly.
- Inner wrapper: "flex flex-wrap items-end gap-zw-md".
- Search: "min-w-0 basis-full @5xl:min-w-60 @5xl:flex-1 @5xl:basis-60".
  - Below a 64rem (1024px) form width it takes a full first row.
  - At or above that width it shares the single row with a 15rem (240px) floor, so it can never collapse.
- Status: "min-w-40 flex-1 @5xl:w-60 @5xl:flex-none". Sort: "min-w-40 flex-1 @5xl:w-56 @5xl:flex-none".
  - On the second row they share the width equally, with a 10rem (160px) floor each.
  - On the single row they keep the previous 240 / 224px widths.
- Apply / Clear: "flex shrink-0 gap-2". They never shrink; if there is no room they wrap rather than squeeze.
Unchanged:
- the form's method, action, role="search", field names (q, status, sort), test ids, labels, placeholder and maxLength;
- the Clear href (directoryHref with search "" and status "all", page 1);
- all filter / sort / pagination logic and query parameters;
- the panel styling (border, surface, padding, shadow);
- the components (Input, Select, Button, LinkButton) and Brand Lock v2 tokens.
DOM order equals visual order, so Tab order is unchanged.
