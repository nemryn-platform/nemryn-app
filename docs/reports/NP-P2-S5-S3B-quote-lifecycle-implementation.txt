1. EXECUTIVE SUMMARY
======================================================================
S3B completes the operational quote lifecycle on the existing Opportunity "Estimates & quotes" panel, using existing
components only:
- Mark sent: a review of the server snapshot, then a confirmation;
- record the customer's reported acceptance or decline;
- Revise: a new draft with a stable key, edited with the existing editor; marking it sent supersedes the original
  atomically;
- withdraw a SENT quote, with a required reason.
It also implements two newly approved decisions:
- OD-Q15 = A, recorded as ZD-222. Quote lifecycle events are written to plus_activities in the same transaction as the
  transition. They have a tenant-scoped quote reference (composite FK (quote_id, organization_id, opportunity_id)) and
  carry no body or amounts. They appear on the Opportunity history, the Contact timeline and the Growth dashboard feed.
- OD-Q16 = A, recorded as ZD-223. Mark sent for a do-not-contact contact requires an explicit staff acknowledgment.
  - It is enforced in the DATABASE: one plus_mark_quote_sent with a trailing p_dnc_acknowledged boolean DEFAULT false.
    It reads the CURRENT flag under a lock.
  - It is audited. It is never consent, never changes the contact, and nothing is sent.
- The outdated Stage-panel note ("Nemryn hasn't created, sent or received a quote") is replaced with truthful,
  staff-recorded wording.

9. QUOTE ACTIVITY-LINKAGE ARCHITECTURE
======================================================================
- Tenant scope: the composite FK makes it impossible for a quote event to reference another organization's quote, or a
  quote of another opportunity in the same organization.
  - VERIFIED (lifecycle F1): both raise 23503.
- The contact matches the opportunity: _plus_quote_activity always writes the LOCKED opportunity's primary_contact_id,
  and the guard trigger refuses any other contact (F2: ZW006).
  - Historical events keep the contact of the time if the opportunity's contact later changes.
- Required reference: quote types without opportunity / quote → CHECK (F4). Non-quote types with a quote reference →
  CHECK (F4). Body on a quote event → CHECK (F3). A status that doesn't match the type → CHECK (F3).
- Existing activities: nullable columns; all constraints validated; no rows changed (upgrade rehearsal: identical on
  the 12 original columns, new columns NULL).
- Clients cannot insert or update activities: no privilege, 42501 (F5).
- Reads: the three timeline RPCs join plus_quotes on (quote_id, organization_id) and return quote_id, quote_number,
  quote_kind, quote_status and related_quote_number. They never return prices (T12).

10. ACTIVITY EVENT SEMANTICS
======================================================================
| Event | Written when | quote_id | quote_status |
|---|---|---|---|
| quote_sent | a draft is marked sent | the sent quote | sent |
| quote_status_changed | acceptance recorded / decline recorded | that quote | accepted / declined |
| quote_status_changed | a revision is marked sent | the PREDECESSOR | superseded |
| quote_status_changed | a SENT quote is withdrawn (draft withdrawal is audit-only) | that quote | withdrawn |
| quote_revised (new type) | a revision draft is created | the NEW revision | draft |

- Draft creation, draft edits and draft withdrawal write no timeline event (work in progress; audit only).
- A revision event names the revised quote and a superseded event names the replacing revision, through
  related_quote_number.
- Display wording (quoteActivityLine; never an amount; never "online"):
  - "Quote 3 marked sent";
  - "Customer acceptance of Quote 4 recorded" / "Customer decline of Quote 4 recorded";
  - "Quote 6 created as a revision of Quote 4";
  - "Quote 4 replaced by revision Quote 6";
  - "Sent Quote 4 withdrawn".
- Idempotent repeats (already sent, the same response, the same revise key, already withdrawn) write nothing (T10).
  Refusals write nothing (T11; D1).

11. DNC WARNING AND SERVER ENFORCEMENT
======================================================================
- Database (plus_mark_quote_sent):
  - after the opportunity FOR UPDATE lock (the established order), it reads
    `select do_not_contact … from plus_contacts … FOR SHARE` for the opportunity's primary contact;
  - if the flag is true and p_dnc_acknowledged is not true, it raises ZW004 dnc_acknowledgment_required before any write;
  - the audit row plus_quote_sent gains contact_do_not_contact (the flag it saw) and dnc_acknowledged (true only when the
    flag was on and acknowledged);
  - the contact row is never updated (asserted in SQL D5, unit tests and E2E N3).
- Bypass attempts (VERIFIED):
  - the 3-argument call, an explicit false, NULL, and a PostgREST-style named call without the parameter are all
    refused (D1–D3, E2E N4, upgrade rehearsal);
  - there is exactly one function, so there is no overload to pick (S1).
- A flag change between opening the dialog and submitting:
  - turned ON: the unacknowledged submit is refused; the dialog then shows the warning and requires the checkbox; the
    acknowledged retry succeeds (SQL D9, E2E N5 / N6);
  - turned OFF: an acknowledged submit succeeds and is audited truthfully as false / false (D8).
- Concurrency (FOR SHARE versus the contact updater's FOR UPDATE):
  - a preference change committed first means the waiting send is refused (CONC-Q13);
  - a send first means the change waits and the send is audited with the flag it saw (CONC-Q13b);
  - the wait in Q13b was below the script's 1-second timer resolution, so the ordering was asserted from the outcome,
    not from timing.
- Retries: a repeated acknowledged confirmation is a no-op, with no duplicate event or audit (D6, E2E X1).
- UI copy: Mark sent records that the team shared the price outside Nemryn; Nemryn sends nothing; it isn't proof of
  delivery. The warning says the acknowledgment doesn't change the preference, isn't consent, and doesn't allow emails,
  texts or future outreach. The confirm button stays disabled until the box is ticked.
