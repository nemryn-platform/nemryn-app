1. WHAT WAS BUILT
======================================================================================================================
Workflow: Completed Trip -> Create invoice (draft) -> edit charges -> Issue -> Record payment -> Print receipt / invoice.

- Sidebar: Administration -> Billing (Organization Admins only, like Settings). The placeholder page is replaced.
- Billing page (/operations/billing): tiles (outstanding, overdue, collected this month, trips ready to invoice);
  "Ready to invoice" (completed, uninvoiced trips, Create invoice per row); "Invoices" (All / Open / Overdue / Drafts /
  Paid / Void, search by number / bill-to / passenger, pagination). Derived state + Overdue badge.
- Create invoice (/operations/billing/new?trip=…): the passenger's other uninvoiced completed trips (checkboxes, the
  trip pre-selected); bill-to = passenger / the trip's requester (default when present) / a facility on the trips /
  someone else (typed); optional Plus quote (only when Plus is readable and a sent / accepted quote is linked to the
  trip's request). Creates a DRAFT only. An already-invoiced trip explains and links its invoice.
- Invoice page (/operations/billing/invoices/[id]):
    draft  — edit bill-to contact, charges (description, quantity, price; add / remove; live totals with the database's
             rounding), discount, terms; Save; Issue (issue date <= today, due date default +15 days, confirmation);
             Discard draft (trips freed, no number used).
    issued — frozen charges and bill-to; Record payment (cash / check / card on an outside terminal / bank transfer /
             other; date, reference, note; overpayment refused); payment history with Reversed badges; Reverse
             (reason required, explains it is a correction, not a refund); Void (reason required; only while nothing
             is paid net of reversals); Print invoice; Receipt per payment.
    void   — read-only history with reason; trips can be invoiced again.
- Trip Detail: Billing panel on completed trips for Organization Admins ("Create invoice" or "INV-000001 · Paid ·
  balance"). Nothing else on Trip Detail changes.
- Print views (authenticated, organization-scoped, no public links): /invoice-print/[id] (org header, number, issue /
  due, bill-to snapshot, passenger, lines, subtotal / discount / total / paid / balance, payments with reversals marked;
  VOID banner) and /receipt-print/[paymentId] (receipt INV-000001-R1, amount, date, method, reference; a reversed
  payment shows "PAYMENT REVERSED … not proof of payment or of a refund"). Drafts are not printable.
- Numbering format: INV-000123 (per organization); receipts INV-000123-R1, -R2 …

2. DATABASE (two additive migrations; isolated stack only)
======================================================================================================================
20261027100000_core_billing_foundation.sql
  billing_invoice_counters, billing_invoices, billing_invoice_trips, billing_invoice_lines, billing_payments.
  Composite (id, organization_id) FKs to passengers / requests / facilities / trips / plus_quotes (optional);
  partial unique index: a trip on at most ONE non-void invoice; lines may reference only trips on their invoice (FK);
  money as bigint cents, USD only, total = subtotal − discount checked; shape checks for draft / issued / void.
  Triggers (also against direct owner edits — R4):
    invoices: identity fixed; only draft→issued and issued→void; frozen after issue except void columns; only drafts
              deletable;
    lines / trip links: change only while the invoice is a draft (links may only be released on void);
    payments: append-only — UPDATE / DELETE / TRUNCATE refused; entries only on issued invoices; a reversal mirrors
              exactly one payment of the same invoice (FK + unique: once).
  RLS on every table: SELECT for Organization Admins of the same organization; no write grants (RPC only).
20261027110000_core_billing_rpcs.sql
  billing_create_invoice_draft · billing_update_invoice_draft · billing_discard_invoice_draft · billing_issue_invoice ·
  billing_void_invoice · billing_record_payment · billing_reverse_payment · billing_list_billable_trips ·
  billing_list_invoices · billing_get_invoice · billing_trip_status · billing_summary (+ internal helpers).
  SECURITY DEFINER, search_path pinned, auth + Organization Admin re-checked (ZW001 / ZW002), invoice row locked,
  expected_version (ZW003), idempotency keys (create / payment / reversal), counter row lock for numbers, audit_events
  row per action (ids / amounts / statuses only — no names, references or notes).
R1 multi-trip: same organization, completed, ONE passenger, not on another active invoice; bill-to linked to EVERY trip
   (passenger = their passenger; requester = a request of the trips AND every trip requested by that same requester; facility = pickup / destination of every trip;
   other = typed name).
R2: reversal = correction entry with reason, once; payment / reversal / void serialize on the invoice lock; void
   only at net zero; balances derived (never stored); receipts mark reversed payments.
R3: quote import optional; needs Plus read + sent / accepted quote attributed to every trip's request; its components
   become per-trip draft lines INSTEAD of the trip line (never both); quote number + kind snapshotted, so the invoice
   keeps working without Plus.
R4: print routes behind requireOrganizationAdminAccess + RLS / RPC; no public links; server actions log only error
   codes; database-level immutability as above.
Trips, assignments, Proof of Service, Core intake and Plus tables are not modified.

6. KNOWN LIMITATIONS
======================================================================================================================
- One passenger per invoice (R1); facility batch billing deferred.
- Prices are entered by hand or copied from a Plus quote; no rate cards, tax, credits or refunds (reversal = correction).
- No email / PDF sending: staff print or save PDF from the browser.
- Who recorded a payment is not shown in the UI (audit_events keeps the actor).
- No-show / cancellation fees not invoiceable (completed trips only, D3).
- No tax-ID field on the invoice header (organizations has none); business name / address / phone / email are used.
- Dispatchers have no billing access in the MVP (D2).
- "Collected this month" uses payment received dates (reversals by their recording date).
