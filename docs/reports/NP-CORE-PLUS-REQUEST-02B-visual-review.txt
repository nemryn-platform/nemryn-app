======================================================================================================================
2. DESIGN-SYSTEM CONFORMANCE
======================================================================================================================
  - Only existing primitives and tokens: Panel, Button (primary / outline / text, size sm, loading), Input, Select,
    the bordered sub-card pattern already used by the "Link existing contact" editor, the warning-border box, the
    Growth form's Do-not-contact card, and typography tokens. No new colours, components or visual language.
  - The inline editor matches the existing "Track in Plus" / "Correct link" editor: a rounded bordered card inside the
    panel, with actions at the bottom left.
  - The form is a single column, because the panel sits in the narrow right-hand column at 1440 and 1024. At 768 the
    column stacks below the main content and the panel goes full width.

======================================================================================================================
3. RESPONSIVE AND ACCESSIBILITY CHECKS (automated in the browser run; section 3 of the test results)
======================================================================================================================
                                   1440    1024    768
  horizontal overflow (buttons)     0       0       0
  horizontal overflow (form)        0       0       0
  horizontal overflow (duplicates)  0       —*      0       * 1024 was screenshot-only
  horizontal overflow (linked)      —       —       0
  - Labels: every input and select in the form has an associated <label> (checked at all three widths). The
    checkbox's label wraps it.
  - Errors: field errors use the Input component's aria-invalid + aria-describedby. Form-level and server errors
    use role="alert". The duplicates explanation uses role="alert", and success notices use role="status".
  - Focus: opening the form focuses Name, and DOM order matches visual order (Name → Phone → Email → Contact type →
    Preferred channel → Owner → Do not contact → submit → Cancel). Duplicates come before the fields, so "Link this
    contact" is reached first.
  - Pending: while saving, the fields and buttons are disabled and the submit button shows its loading state
    (verified: the button is disabled 60 ms after the click).

======================================================================================================================
4. OBSERVATIONS (no change made; owner may decide)
======================================================================================================================
  O1  At 1440 and 1024 the full form is tall in the narrow right column (about 1,000 px). It is usable and consistent
      with the existing editor, but a dialog or a two-column field grid would be a design change. Not done; the
      handoff asked for inline and no competing design.
  O2  "Open in Plus" sits next to the contact name, which is itself already a link to the same contact. It is kept
      as the explicit action the design asked for.
  O3  Not done in Stage B: a keyboard-only walkthrough and an axe scan. Recommended for the Stage C suite.
