8. DATABASE UNIQUENESS AND INVARIANT IMPLEMENTATION
======================================================================
1. Preflight (a DO block, first statement):
   - counts opportunities with more than one 'draft' row and more than one 'sent' row;
   - if any exist, it raises P0001 'od_q12_preflight_failed: …', so the whole migration rolls back and nothing is
     created, deleted or changed. VERIFIED in section 19.
2. Indexes:
   - plus_quotes_one_draft_per_opportunity_idx: UNIQUE (organization_id, opportunity_id) WHERE status = 'draft';
   - plus_quotes_one_sent_per_opportunity_idx: UNIQUE (organization_id, opportunity_id) WHERE status = 'sent'.
   accepted / declined / superseded / withdrawn rows are not indexed, so history is unrestricted (SQL Q10). Indexes are
   checked immediately, statement by statement.
3. Why both an RPC check and an index:
   - every quote writer locks the opportunity FOR UPDATE first (the S1 lock order), so a concurrent writer waits and
     then sees the committed row: the domain check gives a clean ZW004;
   - the index is the backstop for every other path (SQL Q11: an owner INSERT of a second draft → unique_violation);
   - a backstop violation inside the RPCs is mapped to the same domain error, never to constraint text.
4. Expired is not a status. A stored 'sent' quote past its validity still holds the sent slot (SQL Q12).
Read-only release query: docs/reports/NP-P2-S5-S2-od-q12-duplicate-check.sql. It returns one summary row (total, drafts,
sent, violation) plus offender ids only. Production result: 0 quotes, violation false.

10. REVISION / SUPERSESSION COMPATIBILITY
======================================================================
- A sent quote and its revision draft coexist (one draft + one sent; SQL Q8).
- Sending the revision supersedes the predecessor, then sends the revision. Exactly one sent remains, and the
  predecessor's snapshot is unchanged (SQL Q9; upgrade rehearsal: predecessor superseded at total 21500, 1 sent row).
- If the predecessor is no longer sent (accepted, withdrawn), the revision cannot be sent (ZW004
  revision_base_not_current; S1 L20; concurrency Q6 / Q12).
- A revision cannot cross organizations or opportunities: the composite FK on (supersedes_quote_id, organization_id,
  opportunity_id) (S1 L21, still passing).
- Concurrency:
  - CONC-Q12: sending a revision while its predecessor is being withdrawn → exactly one wins; never two sent; never a
    half-applied supersession;
  - CONC-Q10: an independent create racing a revise → exactly one draft.
- No revise UI in S2. A revision draft created through the RPC appears in the panel as the Active draft, labelled
  "Revision of <ref>", and can be edited or withdrawn like any draft.

13. PRICING PARSER AND SERVER TOTAL HANDLING
======================================================================
src/lib/plus/quotes-core.ts is pure and has no runtime imports.
- parseMoneyToCents is exact string arithmetic:
  - accepts "75", "75.00", ".5", "$1,234.56" (commas only as thousands separators);
  - two decimals at most;
  - refuses negatives, junk, exponents, extra decimals, and anything over $100,000.00 (the S1 per-line limit; the digit
    length is checked before any conversion);
  - cents = integer dollars × 100 + integer fraction, with no floating-point multiplication or rounding (a unit test
    asserts there is no Math.round / parseFloat / toFixed);
  - examples: 4.35 → 435, 1.10 → 110, 0.29 → 29.
- formatCents uses integer arithmetic ("$1,234.56").
- centsToInput round-trips with parseMoneyToCents (tested).
- validateQuoteForm:
  - the same rules run in the client preview and in the server action;
  - totals are integer sums;
  - discount ≤ charges;
  - other label if and only if other > 0, ≤ 60;
  - miles: one decimal at most, ≤ 99,999.9;
  - kind / service / round trip closed sets;
  - Valid until must be a real date on or after the organization-local today;
  - terms ≤ 500.
- JSON / bigint: the RPC arguments are plain JS integers, far inside the safe range. No BigInt is ever put in a payload.
  bigint results arrive as JSON numbers and are read with Number().
- Server authority:
  - the actions send only the parsed components, never a total (asserted by a unit test);
  - the database recomputes and CHECKs the total;
  - the UI shows the RPC's returned total_cents and then re-reads the list.

15. IDEMPOTENCY AND CONCURRENCY
======================================================================
- Create:
  - one idempotency key per intended draft ("quote-<uuid>"), generated when the editor opens;
  - stored in sessionStorage (nemryn.plus.quote.create.<opportunity>) from submit until a confirmed result;
  - a retry in the same dialog, a double click, or reopening after an ambiguous failure reuses the SAME key;
  - the key is cleared only after a confirmed success;
  - the database returns the original draft (changed=false), and the person sees "This draft had already been saved;
    nothing new was added." (E2E E7a: the first attempt landed but its response was lost, then a double click → exactly
    one draft).
- Edit / withdraw: optimistic concurrency on the version that was opened.
- Database, verified under real concurrency (section 16):
  - same-key double create → 1;
  - six different-key creates on one opportunity → 1 draft + 5 ZW004 draft_exists;
  - six creates on six opportunities → consecutive numbers;
  - create vs revise → 1 draft;
  - double Mark sent → 1 transition and 1 stage row;
  - revision send vs predecessor withdraw → one winner, never two sent;
  - plus the S1 races (edit / edit, edit / send, revise / accept, two revisions, Lost / send, accept / withdraw).
