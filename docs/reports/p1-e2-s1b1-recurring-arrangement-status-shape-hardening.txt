------------------------------------------------------------------------
ORIGINAL GAP
------------------------------------------------------------------------
S1B's own status-shape constraint enforced only one direction:
`status <> 'paused' or paused_at is not null` — a paused arrangement
must record when it was paused, but nothing prevented an ACTIVE
arrangement from simultaneously carrying a non-null `paused_at`. This
contradicted the already-locked S1A1 resume semantics (`paused →
active` clears `paused_at` back to null) — a row shaped
`status='active', paused_at=<some timestamp>` was schema-legal under
S1B but represents a state the locked resume transition should never
actually produce, and nothing at the schema level said so.

Since S1B has never been committed, pushed, or deployed, the correct
fix is to make the ORIGINAL migration file represent the correct schema
from the start — not to layer a second migration on top of a mistake
that never left local development, per this phase's own explicit
instruction.

------------------------------------------------------------------------
CORRECTED STATUS SHAPE
------------------------------------------------------------------------
`supabase/migrations/20260917090000_recurring_arrangements_foundation.sql`
edited in place (no new migration file). The three one-directional/
partial CHECK constraints from the original S1B version were replaced
with exactly two constraints that together pin down the full locked
matrix:

  check (
    (status = 'active' and paused_at is null)
    or (status = 'paused' and paused_at is not null)
    or status = 'ended'
  ),
  check (
    (status in ('active', 'paused') and ended_at is null and ended_reason is null)
    or (status = 'ended' and ended_at is not null and ended_reason is not null and btrim(ended_reason) <> '')
  ),

Resulting permitted shapes, exactly as locked:
  ACTIVE: paused_at NULL, ended_at NULL, ended_reason NULL.
  PAUSED: paused_at NOT NULL, ended_at NULL, ended_reason NULL.
  ENDED:  ended_at NOT NULL, ended_reason non-blank, paused_at may be
          NULL or NOT NULL (both a terminal state reached directly from
          active and one reached directly from paused, retaining
          paused_at as history, remain valid row shapes — S1A1 never
          settled which one S1D should produce, and this migration
          still does not presume an answer).

No trigger and no transition logic was added — this is static row-
shape integrity only, enforced identically to every other CHECK
constraint already on this table. `active → paused`, `paused → active`,
`active → ended`, and `paused → ended` are not implemented anywhere;
S1D still owns every controlled lifecycle RPC.

------------------------------------------------------------------------
ENDED-FROM-PAUSED COMPATIBILITY
------------------------------------------------------------------------
The explicit compatibility requirement — that the schema must continue
allowing a future S1D flow to end an arrangement directly from paused
without this phase deciding whether `paused_at` is retained or cleared
— is satisfied and directly proven by RA-45: a row shaped
`status='ended', paused_at=<a real prior timestamp>, ended_at=<now>,
ended_reason='ended from paused'` is accepted by the corrected
constraint. No schema surgery is required in S1D for either eventual
procedural choice (clear `paused_at` on end-from-paused, or retain it
as history) — both produce a row shape this constraint already permits.
