4. update_trip_details
======================================================================
  Signature (as reviewed):
    (p_trip_id uuid, p_expected_updated_at timestamptz, p_scheduled_pickup_at timestamptz, p_appointment_at timestamptz,
     p_pickup_description text, p_pickup_facility_id uuid, p_destination_description text,
     p_destination_facility_id uuid, p_instructions text, p_assistance_notes text) returns trip_details_update_result
  Authorization:
    - has_org_role(org of the TRIP ROW, [organization_admin, dispatcher]) -- active membership AND active
      organization. Otherwise ZW002, with no existence oracle (Driver, foreign tenant, inactive membership, suspended
      organization, Platform Admin without membership, not found).
    - No auth.uid() -> ZW001. anon: no EXECUTE.
  Owned fields (full replacement): scheduled_pickup_at, appointment_at, pickup_description, pickup_facility_id,
    destination_description, destination_facility_id, instructions, assistance_notes.
  Never touched: passenger_id, request_id, recurring_arrangement_id, organization_id, state, duration (still
    set_trip_expected_duration), wheelchair (still set_trip_wheelchair_requirement), lifecycle timestamps, assignments.
  Order: row lock FOR UPDATE -> concurrency token -> validation -> changed set -> no-op exit -> timing / facility /
    recurring rules -> lifecycle matrix -> en-route date rule -> UPDATE only the changed columns -> one event + one
    audit row.

  scheduled                      all 8 fields (pickup DATE and TIME may change)

6. SERVICE-DATE RULES
======================================================================
  En-route (D-5):
    - A changed pickup whose (instant AT TIME ZONE organization timezone)::date differs from the current one -> ZW004.
    - A first pickup on a pickup-less trip has no date to keep and is allowed.
  Recurring occurrence (every state):
    - (instant AT TIME ZONE arrangement timezone)::date must stay equal -> otherwise ZW006.
    - This is the same expression create_trip_for_recurring_occurrence and recurring-care use for occurrence
      identity, so an occurrence can never be moved to another occurrence date and the original date can never
      re-appear as "missing".
  DST:
    - The database comparison uses the real IANA timezone (no manual offsets).
    - The UI / action layer converts input with organizationLocalToUtc (nonexistent / ambiguous local times refused,
      never guessed) and pre-checks with localDateKeyOf (Intl, DST-honest).
    - A unit test pins the fall-back day: 00:30 EDT and 23:30 EST are the same local date.

======================================================================
  - Descriptions: trimmed, required, <= 2000.
  - Instructions / assistance notes: trimmed, blank -> NULL. create_trip applies no length bound to these, and none

  - A set pickup can not be cleared.

8. CONCURRENCY
======================================================================
  - p_expected_updated_at must equal trips.updated_at under the row lock; otherwise ZW003.
  - Any other edit, a driver lifecycle step, or a duration / wheelchair change bumps updated_at.
  - UI:
      - message: "This trip changed since you opened it. Refresh and review the latest details."
      - the typed values stay visible;
      - Refresh reloads server truth and closes the dialog; reopening shows the latest values (E2E D2-D4).
  - A replayed save carries the old token -> ZW003.
  - No-op: no UPDATE, no updated_at bump, no audit, no event.
