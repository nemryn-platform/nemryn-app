3. INDEPENDENT PROPOSAL FOR THE P6 / C1 / C2 FAILURES ON MAIN (not implemented; PR #44 not consulted or copied)
======================================================================================================================
  Cause (verified in 02C): migration 20261027110000_core_billing_rpcs.sql (NP-BILL-P1, be6844e).
  billing_create_invoice_draft line 313: `if not public.plus_can_read(p_organization_id) then raise … 'ZW002'` guards
  the OPTIONAL p_source_quote_id. The three tests forbid any Core function from referencing Plus helpers or tables.
  The dependency is real: Core billing reads Plus entitlement when an invoice is drafted from a quote.

  Options for a separate, small main-only change (owner choice):
    M1  (recommended) Record the dependency as an explicit, documented exception:
          - a decision-register entry: "Core billing may read Plus entitlement only to validate an optional source
            quote"
          - add billing_create_invoice_draft by name to the allow-lists of P6 / C1 / C2, with a comment citing that
            entry
        Tests and documentation only; no function change. The boundary rule stays enforced for every other Core
        function.
    M2  Move the quote check into a Plus-owned helper (for example _plus_invoice_source_quote(org, quote_id)) that
        billing calls. The regexes would then stop matching, but Core would still depend on Plus. That hides the
        dependency rather than removing it, so it is NOT recommended unless the tests are extended to flag `_plus_`
        calls from Core.
    M3  Drop the entitlement check from billing. NOT recommended: it changes released billing behaviour.
  Coordination: PR #44 changes billing in this area too. Whichever lands second must reconcile. A main fix should
  be prepared as its own branch from origin/main, never from the FIN branch.
