PWA ARCHITECTURE
============================================================
A delivery layer over the unchanged Driver domain:
 - /driver.webmanifest (route handler, static) and /sw.js (route handler, static per build) — both public, tenant-free, excluded from the session proxy.
 - /offline (public static page) and /api/ping (204, no-store reachability probe).
 - Client pieces inside the Driver shell only: DriverServiceWorker (registration + update notice), DriverNetworkStatus (global indicator), DriverInstallCard (Profile only).
 - Icons /pwa/* generated from the approved brand master by scripts/generate-pwa-icons.mjs (artwork reused byte-for-byte; only wrapped in a scale transform for maskable/apple).
 - Build id: next.config.ts sets NEXT_PUBLIC_BUILD_ID (Vercel commit SHA, else a local timestamp) and generateBuildId, so every deployment emits a different sw.js.
 - Service workers register in PRODUCTION builds only (dev chunks are not hashed).

SERVICE WORKER
============================================================
Scope "/driver" (deliberately without trailing slash: a scope of "/driver/" would not control the start page /driver itself — found in the first E2E run and fixed). Emitted per build by src/lib/pwa/service-worker.ts; the unit tests execute the exact emitted source in a sandbox.
 - install: precache the public /offline page, its own CSS/JS/fonts and the icons/brand symbol with credentials omitted. It does NOT skipWaiting.
 - activate: delete older Nemryn caches, claim clients.
 - fetch: only GET, same-origin. Navigations: network only; on network failure serve cached /offline; any server response (401/404/500…) passes through unchanged. Allowlisted static assets (/_next/static, /pwa, /brand): cache-first, only ok+basic responses stored. Everything else: NOT intercepted.
 - message: SKIP_WAITING (update) and LOGOUT (purge).
 - No background sync, no periodic sync, no push handlers.

NETWORK FAILURE
============================================================
Lifecycle actions and Report Issue now treat an unreachable network as an explicit, retryable failure (isNetworkFailure): message "Can't reach Nemryn. Your update was not sent. Check your connection, then try again."; no optimistic state, nothing queued (no IndexedDB/localStorage), no replay; the screen keeps its context (page did not reload or navigate; state still "Assigned"); the button is enabled again; router.refresh is skipped for a network failure (it would itself fail). Report Issue is now controlled-input so React's post-action form reset cannot erase what the Driver typed; text and choice retained (verified). Server truth: trips.state and trip_events unchanged, no exception created while offline; after reconnect the retry succeeds exactly once (1 exception, 1 notification event). Design note: if only a RESPONSE is lost, a retry sends the same expected-current-state and the database returns STALE_STATE (existing ZW003 handling) instead of double-applying.
