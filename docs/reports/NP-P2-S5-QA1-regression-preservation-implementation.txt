======================================================================
1. No credentials or secrets are tracked. A scan of tests/ for JWTs, provider keys, *_KEY= / PASSWORD= values, real

   - the ACK gate (verified: all 3 refuse without it, before any connection);
   - the linked-project check;
   - q() allows only ONE SELECT / WITH statement, refuses write / DDL / transaction keywords and a second statement
     (string literals are blanked before screening, so `';'` and words inside quotes are data);
   - the browser only views pages.
   A scan of all 40 SQL strings in the 3 scripts: 0 keyword false positives.
5. Fixture reset requirements are explicit: the runner resets and verifies (latest migration, 0 quotes, 0 contacts)
   before EVERY suite, and the README documents the requirement.
6. No shared state: one process per suite, a fresh database per suite, and a throw-away Chrome profile per session
   (deleted on close) under the artifacts directory.
7. axe-core and pdf.js are pinned devDependencies; there are no CDN fetches at test time.
8. The new lint warnings are removed: the unused `byId` (print script) and `catch (e)` (integrated suite). ESLint on
   tests/ reports 0 problems.
9. Screenshots, PDFs, logs and profiles are written OUTSIDE the repository. An in-repo artifacts directory is refused
   (verified).
10. No credential or sensitive configuration logging (scan above). The production scripts print only check results
    and record counts.

- U2 focus not restored after Cancel / Close, WCAG 2.2 SC 2.4.3. Checks: KEY Edit draft → Cancel, Edit draft →
  Close (X), Record accepted → Cancel.
UNEXPECTED — found and resolved during QA1 (a fixture-coverage gap, not a product change):
- On the first full runner pass, s4-a11y reported 19 PASS / 7 FAIL. The "AXE Estimates & Quotes directory" check
  PASSED.
- Cause: in S4 the a11y suite ran after the integrated journey on the same database, so the directory contained
  Withdrawn / Superseded quotes whose StatusBadge "cancelled" tone carries the U1 contrast pair. With the runner's
  per-suite fresh reset, the suite's own fixtures contained only draft / sent quotes, so that badge was never rendered.
  That's a lost-coverage false pass, NOT a fix.
- Resolution: the a11y suite now creates its own history rows (a revised-and-superseded quote and a withdrawn
  draft), so every badge tone renders on any fresh database. Its assertions are unchanged. Re-run from a fresh reset:
  18 / 8, the exact S4 baseline, and the final full pass confirms it.
- Hardening: the runner now flags "REVIEW: only n of 8 known checks failed (partial fix or lost coverage)" whenever
  some but not all known checks fail.
Harness exceptions (pre-existing; documented; not part of the relevant subset run here):
- request_decision_expand_compat 8 / 10;

8. KNOWN LIMITATIONS
======================================================================
- The suites need a running isolated stack and a locally served build. They are not wired into automatic CI; that
  would need a CI job provisioning a local Supabase and Chrome, which is a separate, owner-approved step. The
  production scripts must never be in CI.
- The CDP harness drives Chrome only (no Safari / Firefox). The default Chrome path is macOS (configurable).
- A full run takes about 35–40 minutes because of the fresh reset per suite. --no-reset is available for manual use
  (S3A then needs an empty quote database).
- The README describes the isolated-stack setup, but the stack itself is not scripted in the repository
  (project_id / ports are local choices).
- The production scripts' live behaviour is unchanged from S4. They were deliberately NOT executed in QA1 (no
  production access), so their tracked versions are verified statically (syntax, lint, guard refusal, assertion
