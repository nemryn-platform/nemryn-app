2. FINDINGS
======================================================================================================================
F-1 RESOLVED (ZD-286) Tenants could read the enablement reason / approval_ref through RLS. The client grant and
    policy are removed; the status RPC returns enabled / version / set_at only; full details are Platform-Admin-only.
F-2 (INFO) The approval_ref check is syntactic. It proves a reference to NP-LAUNCH-02 was entered, not that the GO
    exists. It is a guardrail against accidental live enablement, not an authorization system.
F-3 (INFO, ZD-287) A disabled organization can't make corrections either. Intended: no temporary enablement for
    corrections (EC-1). A scoped correction-only capability, or an approved equivalent, is required before the first
    live enablement (EC-6).
F-4 (INFO) billing_write_status errors fail closed in the UI (actions hidden, "unavailable" warning). No path shows
    write actions on an unknown state.
F-5 (INFO) Old app builds (main, PR #44) show write actions for a disabled organization. A refused write shows their
    generic ZW004 message ("isn't possible in the invoice's current state"). Misleading, but safe: nothing is written.
    Closed by deploying the P1G app (release-compatibility report).
F-6 RESOLVED The gate-only reversal is withdrawn. The combined rollback is guarded (empty ledger, no live record,
    billing_payments empty) and locks all billing tables first.
F-7 (MEDIUM, closed by the package; open for any non-package release) M1's zero-row check takes no write-blocking
    lock, so a BILL-P1 payment could commit before billing_payments is retired later in M1. The package locks the
    BILL-P1 tables first and re-asserts zero payments. Do not release FIN-P1 with a plain `db push` while the app can
    still record payments.
F-8 (INFO) `supabase db query -f` cannot run multi-statement files (prepared statement). The package and rollback
    must be run with psql -f. The FIN-P1 reversal header's `supabase db query --linked -f` suggestion is unverified.
F-9 RESOLVED (HIGH before the fix, owner-reported) The rollback checked for financial records before locking. Reproduced:
    a receipt (S0) and a live enablement (S4c) committed during the window were dropped with their tables. Fixed:
    locks first, then all checks; the live check now also covers the history.
F-10 RESOLVED (found while testing F-9) EXCLUSIVE locks plus later DROPs (ACCESS EXCLUSIVE) deadlocked against a
    waiting writer. Fixed by taking ACCESS EXCLUSIVE once, up front. Trade-off: billing reads wait during the
    seconds-long rollback.
No open HIGH findings; the one MEDIUM finding (F-7) is mitigated by the required release procedure.
