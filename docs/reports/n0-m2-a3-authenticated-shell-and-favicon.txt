5. WHITE-WRAPPER DECISION
-------------------------------
The `<span className="inline-flex items-center rounded-sm bg-white
p-1.5 lg:p-2">` wrapper's ONLY documented purpose (per the sidebar's
own prior inline comment, preserved verbatim in git history) was to
counteract the old Zenward PNG's baked-in opaque white background —
"a small, plain white badge chip behind it... never touching the PNG's
own pixels." It had no other responsibility: no layout role beyond
`inline-flex items-center` (which the parent `<div className="flex h-16
items-center ...">` already provides), no sizing role beyond padding
around the badge itself, no accessibility role.

Since `nemryn-logo-inverse.svg` has no background of its own (a bare
`<g fill="#F7F7F4">` path group, confirmed transparent — this exact
property is why it is the correct dark-background variant in the first
place), the badge's entire reason for existing is gone. It was removed
entirely; the `<Image>` now renders as a direct child of the existing
`h-16 items-center` header row, which still provides correct vertical
centering and horizontal padding (`px-4 lg:px-6`) with zero new
wrapper needed. Confirmed live: no visible artifact, seam, or spacing
regression in any screenshot (§16).

10. DRIVER-SHELL WORDING DECISION
----------------------------------------
File: src/components/driver/DriverLayoutClient.tsx

`getDriverHeaderTitle()`'s fallback branch returned `"Zenward Driver"`
for any pathname not matching one of its five known routes (/driver,
/driver/trips, /driver/trips/[id], /driver/history, /driver/profile).
Changed to `"Driver"` — the phase's own explicitly preferred choice,
NOT "Nemryn Driver" (which would incorrectly imply Nemryn, the
platform, is the driver's transportation employer — the tenant is).

The richer alternative the phase offered — `{organizationName} ·
Driver` — was considered and NOT used: `organizationName` is not
currently threaded into `DriverLayoutClient`'s props (only `driverName`
and `showOperationsLink` are), and adding it would require a new prop
on `DriverLayoutClientProps` plus a change to the parent server
`DriverLayout` to pass `access.organization.organizationName` through.
The phase explicitly said not to introduce new data plumbing for this
label; the plain "Driver" fallback needs none and was preferred for
that reason.

Note on reachability: every actual /driver/* route in this application
(Today, Trips, Trip Detail, History, Profile) is already covered by
this function's five explicit `if` branches — the fallback branch is
defensive/unreachable in current routing, never actually rendered by
any real navigation. The fix was still made because dead code carrying
stale platform branding is still a genuine finding worth correcting,
matching this session's established practice of not leaving stale
brand strings in place merely because they're hard to reach.
