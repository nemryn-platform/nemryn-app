1. ORIGINAL INTERACTION AND ROOT CAUSE
--------------------------------------
- The Requests queue (src/components/operations/requests/RequestsTable.tsx) rendered the passenger (or requester)
  name as the only link to Request Detail.
- The table used the shared DataTable WITHOUT its existing `navigableRows` mode, which Contacts and the Estimates &
  Quotes directory already use (NP-UI-P1a).
- Measured on the baseline build, Org A dispatcher (browser-before.log):
  - a click on the name opened Request Detail;
  - a click on Route, Service, Waiting, Readiness, the Status badge or empty row space did nothing;
  - rows had no hover tint and an "auto" cursor.

3. EXACT IMPLEMENTATION APPROACH
--------------------------------
a) RequestsTable adopts the existing DataTable `navigableRows` convention (same as ContactsTable /
   QuotesDirectoryTable):
   - "use client". The row click handler runs in the browser. Rendering, columns, copy, classes and Brand Lock
     tokens are unchanged.
     - Its props (rows, `now`) are serialisable.
     - formatRequestAge / formatRequestServiceDate are deterministic (server-supplied `now`, UTC calendar
       formatting), so there is no hydration drift.
   - The existing name link (both the passenger and the requester variants) is now marked `data-row-link`,
     data-testid "request-row-link", with `onClick={e => e.stopPropagation()}`, exactly as Contacts / Quotes do.
     The href is unchanged: /operations/requests/{row.id}, the server-supplied id of that row.
   - `navigableRows` is passed to DataTable. DataTable then:
     - adds "cursor-pointer hover:bg-surface-hover focus-within:bg-surface-hover" to rows (the approved subtle
       tint, already used by Contacts / Quotes);
     - follows the row's own link when anything else in the row is clicked.
   - No new buttons, icons, columns or routes. Filters, search, tabs, sorting and pagination are untouched.
b) DataTable's navigation-row handler gets two small safety fixes, for Requests and for the existing Contacts /
   Quotes rows:
   - The row now dispatches a click to its link carrying the original click's modifier keys, instead of a bare
     `a.click()`.
     - Cmd-click on any part of the row opens the request in a new tab, and Shift-click opens a new window, exactly
       as on the link itself.
     - A plain click is unchanged: the Next.js Link performs normal client navigation.
     - Clicks on the link itself were never intercepted, and still are not (the handler ignores clicks whose target
       is inside a real control).
   - The row does not navigate when the click ends a text selection that touches the row
     (`selection.containsNode(row, true)`). Drag-selecting a route or phone, or Shift-extending a selection into a
     row, selects text instead of opening the request.
   - The existing guard is unchanged: a click on any real control inside a row (a, button, input, select,
     textarea, label, summary, role=button/link/checkbox/switch) is left to that control.
   - The Requests rows contain no controls other than the name link; there are no row action buttons in this
     table.

4. ACCESSIBILITY STRATEGY
-------------------------
- One real <a href> per row, the passenger / requester name. It is:
  - the only tab stop in the row, named by its text (no "View" / "Open");
  - opened with Enter natively (no tabIndex, onKeyDown or role on the <tr>);
  - without duplicate focus targets: one Tab moves from row N's link to row N+1's.
- The mouse-only whole-row click is a convenience that duplicates that link. Nothing is reachable only by mouse.
- The table semantics are unchanged: thead with th[scope=col] × 6, tbody rows of td, no nested interactive content.
- Focus: the global 2px :focus-visible outline on the link, and the focused row is tinted (focus-within).
- Native link behaviour is preserved: modified clicks, open in new tab, the context menu, middle-click on the link.

9. REMAINING RISKS
------------------
- Double-click to select a word in a non-link cell opens the request on the first click, before any selection
  exists. This is inherent to any click-to-open row and is the same as Contacts / Quotes. Drag-select and
  Shift-extend work.
- Middle-click on non-link row space does nothing (no auxclick handling); middle-click on the name link opens a new
  tab natively. This is deliberately not emulated, to avoid overriding browser behaviour.
- The DataTable handler change also applies to Contacts and the Quotes directory, with the same benefits there.
  p1a T6 and Quotes strict s3a confirm their destinations are unchanged.
- Screen-reader users hear each row's single link, named by the passenger / requester. No row-level label was added.
