1. CORRECTIONS MADE
=====================================================================================================
  C1 Forward foreign keys removed. Nine forward dependencies were found (F1-F9, domain model section 3.1): account
     links on contacts / activities / opportunities / tasks / attributions, activities -> opportunities, inquiry
     consent before the consent table existed, and quotes -> undesigned pricing rules. Each table is now created
     without the forward column, and the column is added later by an additive, nullable migration with a composite
     FK (precedent: recurring_arrangements.request_id, 20260927120000:24-33). Every replaced CHECK is named and
     validates all existing rows.
  C2 Opportunity contact constraint corrected. A02 used (channel = 'private_pay') = (primary_contact_id is not null),
     which forbade facility opportunities from naming a decision-maker. It is replaced by:
     private_pay => contact required (P2-S1); facility => account required (P3-S1); facility contact optional and
     RPC-checked to belong to the same account.
  C3 Plus online inquiry capability moved into the private-pay MVP (P2-S7). It is a separate boundary: own tables,
     publication, rate-limit ledger, service-role RPCs, route and pages. Submissions land in a triage inbox
     (plus_inquiries); nothing auto-creates a Contact, Opportunity, Core Request, Passenger or Trip.
  C4 Quotes staged. Q1 staff estimates and quotes (plus_quotes, P2-S5) come first; Q2 Core pricing rules after the
     pricing approval; Q3 payments as a separate decision; no billing system.
  C5 Named-staff Plus grants moved from NP-P5 to P1-S3. Growth-only members are a separate owner decision (PD-18).
     A salesperson is never made an Org Admin to reach the CRM.
  C6 Entitlement states refined: new restriction column (read_only | no_access) for 'disabled'; new effective state
     'locked' for security disables; grant holders lose access outside 'write'; historical export is Admin-only.
     Trial default is 14 days (7-30 configurable, one extension of up to 30 days), replacing the A02 90-day cap. No
     Plus state can affect Core.
  C7 Consent ledger moved from NP-P4 to P2-S6 (needed by the inquiry form); sending stays NP-P4.
  C8 Verified-in-source correction: Core memberships has only PK id and unique (organization_id, user_id), and no
     table references it. Composite-FK grants therefore require an additive Core constraint
     unique (id, organization_id) in P1-S3 (PD-20). A02 had not identified this.
  C9 PD-04 (/operations/growth) is now recorded as OWNER-APPROVED.
  C10 Exports reuse the UX1 CSV writer, including the formula-injection fix from P1-PILOT-UX1-CLOSEOUT.
