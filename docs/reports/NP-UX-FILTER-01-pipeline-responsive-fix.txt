1. DEFECT AND ROOT CAUSE
------------------------
File: src/app/operations/growth/pipeline/page.tsx (the filter <form role="search">).
- From the md breakpoint (viewport ≥ 768) the form became ONE flex row:
  - Search: `min-w-0 flex-1`;
  - fixed-width selects: Stage md:w-48 (192px), Source md:w-44 (176px), Owner md:w-44 (176px);
  - then Apply (plus Clear when filtered), with 16px gaps.
- The fixed parts total about 690px (about 760px with Clear). When the form's content width fell below that plus room
  for Search, Search, the only flexible item with min-w-0, shrank to its padding (26px).
- Its "Search" label then visibly overflowed into the Stage label.
- The breakpoint is viewport-based, but the space depends on the collapsible sidebar (expanded from 1024, icon rail
  below). The defect therefore appears in two bands:
  - with the sidebar expanded: Search is 231px at 1280 and 147px at 1180, collapses to 67px at 1100 and 26px at 1024;
  - with the icon rail: 135px at 960 and 75px at 900, then 26px at 860 / 822 / 800 / 768.
  - An active search plus filters (the Clear button present) makes it worse: 26px already at 1100.
- Before measurements: docs/design/concept-b/reviews/ux-filter-01/search-width-before-after.txt.

The same pattern elsewhere (measured, NOT changed; outside this brief's Pipeline scope):

2. FIX (one file; layout classes only)
--------------------------------------
- The form is now a container (`@container`). The layout follows the FORM's own width, not the viewport, so it is
  correct whether the sidebar is expanded or collapsed. This is the existing Tailwind v4 container-query idiom already
  used in OperationsBrief and OnboardingChecklistBanner.
- Inside the form, a `flex flex-wrap items-end gap-zw-md` row.
- When the form is ≥ 64rem (`@5xl`), it is a single row, as before:
  - Search `@5xl:flex-1 @5xl:basis-60 @5xl:min-w-60` is the flexible field and can never go below 15rem; it would
    wrap instead;
  - Stage / Source / Owner keep their previous fixed widths (w-48 / w-44 / w-44);
  - then Apply and Clear.
- When the form is narrower:
  - Search takes a full row (`basis-full`);
  - Stage / Source / Owner share the next row (`flex-1 min-w-40`, i.e. ≥ 10rem each);
  - Apply / Clear (`shrink-0`) sit at the end of that row, and wrap to their own row rather than shrinking if ever
    needed.
- Below md, unchanged: the Operations shell shows its approved "designed for tablet and desktop use" notice.
- Unchanged:
  - the form method / action / role="search" / data-testid;
  - the hidden view / layout inputs;
  - the field names (q, stage, source, owner), the options and the defaults;
  - Apply and Clear (and its href);
  - the Open / Lost / All and Board / List controls;
  - the DOM order (and therefore Tab order);
  - every token / colour / typography.
  - A data-testid "pipeline-filter-search" was added to the Search wrapper (test hook only).
- No route, query parameter, server code, data access or business logic changed.
