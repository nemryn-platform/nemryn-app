1. WHAT WAS BUILT
-----------------
Public routes (app host only, ZD-256):
- Hosted page: GET /inquiry/[publicKey].
- Embed page: GET /embed/inquiry/[publicKey].
- Embed loader: GET /embed/inquiry-form.js.
- Config API: GET /api/plus-inquiries/[publicKey].
- Submit API: POST /api/plus-inquiries/[publicKey]/submit.

Experience:
- A clean, Brand Lock v2 form: the action-primary teal button and the accent-strong organization name. It follows the
  same structure and neutral palette as the approved Core request form, so the public look is consistent.
- Responsive: one column on phones, two columns from sm.
- The headline and intro come from the organization's form; the organization name is shown; "Powered by Nemryn".
- Fields (ZD-246):
  - required: name; phone and/or email; question type; question (≤ 500, with a counter);
  - optional: preferred reply (Either / Phone / Email), who the transportation is for, service, timeframe.
- Services = the form's offered services ∩ what the organization still offers, from the 8 Plus types only.
  airport_transportation is never shown or accepted (ZD-263), including when the organization offers it in Core.
- "This form is for questions. It doesn't book a ride." No address, date of birth, diagnosis, insurance or exact date
  is collected.
- Consent (ZD-252): two SEPARATE, OPTIONAL, UNTICKED boxes using the approved P2-S7 wording (consent text version
  plus-inquiry-consent-v1):
  - "<Org> may follow up with me about transportation services by the contact details above."
  - "Send me news and offers from <Org>."
  A submission records only what was ticked. No consent ledger row is written (that happens at staff conversion, S7-C).
  LEGAL REVIEW OF THIS WORDING IS STILL OUTSTANDING, so real submissions stay disabled (§3).
- States:
  - editing;
  - sending (button disabled; one request in flight);
  - submitted (a focused confirmation; content cleared from memory; "Ask another question");
  - unavailable (the neutral page, identical for every cause);
  - invalid (an error summary with links; focus moved there; fields marked aria-invalid);
  - rate-limited ("Please wait a little while, then try again" — no threshold disclosed);
  - form updated (409 → "Reload the form");
  - server error ("We couldn't send your question right now").
- Privacy:
  - content lives only in React state;
  - the only browser storage is the acquisition-only first-touch context (S4C keys, namespaced
    nemryn:inquiry-form:<key>:acquisition);
  - no tracking scripts, pixels or third-party code;
  - pages are noindex and no-store.

3. SECURITY AND ACTIVATION BEHAVIOUR
------------------------------------
Two independent server-side gates, and BOTH must allow (ZD-259 / ZD-262):
- (1) Global kill switch PLUS_INQUIRY_SUBMISSIONS.
  - ON only when it is exactly "on" (unit-tested: unset, "", "ON", "true", "1", " on" … are all OFF).
  - Checked first on the hosted page, the embed page, the config API and the submit API, BEFORE any database call.
  - Default OFF. No production environment variable was set or changed.
- (2) The per-organization allowlist (plus_inquiry_public_access), plus a published form, an active organization and
  Plus write, all enforced inside the service_role RPCs. The production allowlist is EMPTY.
- When either gate is closed: the identical neutral 404 / unavailable page (no tenant enumeration, no reason).

Submit pipeline:
  kill switch → key format → Origin (only the app's own origins; a missing Origin is allowed and is never the auth
  boundary) → 8 KB cap → JSON → closed-key schema (organizationId / formId / status / contactId … reject the whole
  body) → durable atomic rate limit (5 / client / h, 60 / form / h; the client key is a salted one-way hash of the IP,
  never stored or logged raw) → submit_plus_inquiry (authoritative re-validation; organization resolved ONLY from the
  key).

- Responses: 200 {ok:true} | 400 invalid_request | 404 unavailable | 409 form_changed | 429 try_later |
  503 try_later. They carry no ids, ZW codes, database text or limits.
- Logging: fixed messages only; no key, IP, hash or submitted content.
- Service-role credentials: only server-only modules (`import "server-only"`); nothing reaches the browser.
- Idempotency:
  - one submission reference (UUID) per form instance, reused on retries;
  - the database key unique (organization, key) makes replays and concurrent duplicates store ONE row.
- A submission creates ONLY one plus_inquiries row: no contact, opportunity, Core Request, consent record or
  notification (E2E S2 / Z1).

Embedding:
- the loader builds an isolated iframe and auto-resizes it;
- messages are trusted only from its own iframe AND the Nemryn origin, in the "nemryn-inquiry-form" protocol (the
  Core request-form protocol is ignored);
- the iframe posts its content-free "ready" to "*" and everything else only to the verified parent origin;
- the iframe submits same-origin (no CORS on the API);
- availability, validation, rate limits and tenancy are identical to the hosted page.
- Headers: the hosted page has frame-ancestors 'none' + X-Frame-Options DENY; the embed page has frame-ancestors *;
  both are noindex and no-store; the loader has nosniff and a 5-minute public cache.

5. LOCAL SYNTHETIC DEMONSTRATION (isolated stack only; never production)
------------------------------------------------------------------------
1. Start the isolated app with the switch on, for that process only:
     source ~/NemrynS1Iso/.env.isolated.local && PLUS_INQUIRY_SUBMISSIONS=on npx next start -p 3100
2. Create a published form and allowlist a FICTIONAL organization. The simplest way is the E2E fixtures:
     INQUIRY_E2E_MODE=on node tests/e2e/plus-inquiries/inquiries.e2e.mjs
   It creates and then removes them. For a manual demo, run its fixture SQL block alone. In S7-C this becomes Settings →
   Nemryn Plus → Inquiry form, plus platform_set_plus_inquiry_public_access by a Platform Admin.
3. Open http://localhost:3100/inquiry/<inq_ key>. To embed it on any page:
     <div data-nemryn-inquiry-form="inq_…"></div>
     <script src="http://localhost:3100/embed/inquiry-form.js" async></script>
   In production the script origin is https://app.nemryn.com.
4. Submitted inquiries appear in plus_inquiries (status new). The staff inbox is S7-C.
