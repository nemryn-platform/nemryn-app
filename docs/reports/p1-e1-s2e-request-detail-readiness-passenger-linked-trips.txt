6. DETAIL LOAD CONTRACT
----------------------------
`src/lib/operations/request-detail.ts`, `getRequestDetail(requestId,
organizationId)`:

    export type RequestDetailResult =
      | { status: "ok"; request: RequestDetailData }
      | { status: "unavailable" }
      | { status: "error" };

Mirrors `trip-detail.ts` exactly: a malformed `requestId` (fails a UUID
regex) is rejected BEFORE any query — never lets a raw Postgres
"invalid input syntax for type uuid" error escape as a distinguishable
signal. A well-formed but nonexistent or foreign-org id and a genuinely
nonexistent one both resolve to the SAME `unavailable` result — no
existence oracle. A real query error (on the Request row itself OR on
the Linked Trips query — both treated as equally authoritative, §19/
§27.E) resolves to `error`, never silently downgraded to `unavailable`
or an empty/zero-row `ok` result.
