# Nemryn Driver PWA foundation (P1-PILOT-S5A)

The Driver web experience (`/driver/*`) is an installable Progressive Web App. It is a **delivery/runtime layer over the existing secure Driver domain** (same authentication, `current_driver_id`, assigned-trip reads, lifecycle RPCs, exceptions). It is tenant-neutral: the same for every Nemryn organization; nothing Zenward-specific exists.

## Delivered
Installability, app identity ("Nemryn Driver"), standalone experience, network resilience, update handling, mobile shell polish, a secure cache boundary.

## Not delivered (later decisions)
Background GPS, navigation, push notifications (no VAPID keys / subscription table / permission prompt), offline mutations, store distribution, native wrapper, biometrics.

## Identity
- Manifest `name` **Nemryn Driver**; `short_name` **Nemryn** (never truncated on launchers; the Driver context comes from the full name and the start URL). iOS home-screen title: "Nemryn Driver".
- `start_url` **/driver**, `scope` **/** (the sign-in / select-organization / confirmation pages a Driver passes through stay inside the standalone window), `display: standalone`, `orientation: any` (drivers mount phones landscape; foldables are near-square).
- Theme `#171A1D` (Deep Graphite), background `#F7F7F4` (Mineral White surface) — existing brand values. Tenant identity appears only inside the authenticated workspace (Profile shows the Driver's active organization).
- Manifest `/driver.webmanifest`, icons `/pwa/*` (192, 512, maskable 512, Apple 180) generated by `scripts/generate-pwa-icons.mjs` from the approved brand master (artwork reused unchanged). Manifest link/icons/iOS meta are attached to the Driver layout only; Operations and Platform are not installable.

## Service worker (`/sw.js`, scope `/driver`)
Purpose: app-shell resilience only. Emitted per build (`NEXT_PUBLIC_BUILD_ID` = Vercel commit SHA) so each deployment changes its bytes.
- **Caches only public static assets** (one cache `nemryn-driver-static-<build>`): `/_next/static/**` (cache-first), `/pwa/**`, `/brand/**`, and the public tenant-free `/offline` page (precached at install, with its own CSS/JS/fonts).
- **Navigations:** network only; if the network is unreachable the cached `/offline` page is shown. A server answer (401/403/404/5xx) passes through unchanged — server errors are not "offline".
- **Everything else** (authenticated HTML, RSC payloads, Server Actions/POST, Supabase/API calls) is **not intercepted and never stored**. No Trip/Passenger/address/note/exception/proof/driver data is ever persisted by the PWA. No IndexedDB / localStorage / sessionStorage use.
- Scope has no trailing slash on purpose (`/driver/` would not control the start page `/driver`).
- Registered only in production builds (development chunks are not content-hashed).

## Cache policy for authenticated data
Network-first, **no persistent service-worker cache**. `/driver/**` responses carry `Cache-Control: private, no-store, max-age=0` (also enforced in `next.config.ts`). Offline, the Driver sees an explicit offline state, never stale trip data presented as current.

## Network behaviour
- Global indicator (`DriverNetworkStatus`): "Offline. Trip updates require a connection." after a 2 s debounce; recovery is confirmed by reaching Nemryn (`/api/ping`, 204, no-store) — `navigator.onLine` is only a hint; "Connected" shows briefly, then disappears. Server errors are separate.
- **Mutations under network failure** (lifecycle actions, Report Issue): the request either reaches the server or it did not. On failure the UI shows "Can't reach Nemryn. Your update was not sent. Check your connection, then try again." — no optimistic state, nothing queued, no background sync, typed text kept. The server is authoritative: if only the *response* was lost, a retry sends the same expected-current-state and the database answers `STALE_STATE` rather than applying a transition twice.
- Offline page: "You're offline — Reconnect to view current trip information — Trip updates cannot be sent until your connection returns." No "will sync later".

## Updates
A new worker installs and **waits**. A quiet notice ("A new version of Nemryn is available. [Update]") appears; the app reloads only when the Driver taps Update (or all windows close) — never mid-action. The app also looks for an update when it returns to the foreground and every 30 minutes.

## Logout
The sign-out form also messages the worker (`LOGOUT`): it deletes any Nemryn cache other than the static one and any cached entry that is not an allowlisted public asset. Public static assets remain.

## Install experience
Profile screen only (no modal, no nagging): Chromium/Android shows an **Install app** button once the browser offers `beforeinstallprompt`; iOS/iPadOS Safari shows "tap Share, then Add to Home Screen"; standalone shows "installed app". Installation is never required — the Driver workspace is fully usable in a browser.

## Mobile shell
`viewport-fit=cover`, safe-area top/bottom insets honoured, bottom nav grows with the inset (min 64 px), touch targets ≥ 44 px, keyboard-safe `interactive-widget=resizes-content`, `overscroll-behavior-y: contain` (no accidental pull-to-refresh), capped column on wide screens.

## Boundaries
Location tracking is unchanged (foreground, tap-initiated, no background). No camera capture exists in the Driver workflow, so none was added. External map links unchanged; no map SDK. No Web Push.
